# Ronova Pro V1.5：整份 Mod 攻防与来源终结

初稿：2026-09-27；整 Mod 范围修订：2026-09-28。工程：D:\桌面\ronova_GPT。

**定位：小体积、最高强度的 Pro。用户选定目标 Mod 后，以整份 Mod 为默认攻击、拦截、
任务、来源、存储和客户端处置范围；同 Mod 的其他对象、公共方法和功能一起停用。**
底层沿实际对象、定义、槽位和执行位置直接动作，不增加与攻防效果无关的验证。

本修订依据用户明确选择：停用目标 Mod 的所有方法和功能，接受同 Mod 的其他对象一起失效。
它取代本文件旧版“只处理命中实体、默认保留同 Mod 其他功能”的范围限制。
原有准确操作仍作为执行手段；“准确”用于找到目标 Mod 的真实位置，不再用于缩小到单个实体。

**本轮只写方案。整 Mod 能力尚未实现；build25 的原 A 范围 PASS 不扩展为本修订 PASS。**
[A 批状态](../A-批验收状态.md) 是唯一当前实现入口；旧失败继续保留。
此文件保持为唯一主设计，不另外创建并行主设计、许可体系或验证台账。

## 1. 默认主体、授权范围与交付目标

### 1.1 一次请求处理一个或多个 Mod

攻击主体支持一个 modid、多个明确列出的 modid 或界面多选形成的目标集合。
逐成员解析 Forge 实际 Mod 容器、所属文件及当前已定义 Module／ClassLoader。
“整份 Mod”是处置粒度，不是数量上限；集合中每份目标 Mod 都采用前述整份处置语义。
归属优先使用加载器实际登记和来源记录；名称、包名前缀、注册表命名空间、相同类名均不能独立充当归属。
一次捕获后复用当前代次，不逐方法重算全包哈希，不等遍历完整 JVM 才开始阻断已知目标。

多选集合采用以下共同规则：

- 一个请求发布一次批次目标集合，复用现有 OperationId 和组代次；每个真实作用组保留自己的执行结果。
  批次不是新的分布式事务，不要求所有 Mod 同时结束才允许已知动作生效。
- 重复 modid、同一文件／模块的别名和重叠来源按实际载体合并；同一个句柄、资源或保存效果不得重复释放／提交。
  同载体关联的全部 modid 在输出中列出。
- 单个 modid 不存在、后端不可用或动作失败时单独报告，其他明确指定且可执行的成员继续。
  失败成员不自动替换成通配符，也不回滚其他成员已发生的真实效果。
- 同一共享容器可以合并处理集合内所有目标份额；集合外条目、共享框架及加载器继续工作。
- 总预算按批次限制并在各组间公平轮转，不能给每个 Mod 各开完整全局扫描／后台线程／证明流程。
  单组阻塞不占住其他组的执行门。
- 当前选集在请求时确定；目标 Mod 后续的新类／对象／任务按组策略增量纳入。
  后来加载的其他 Mod 不因同线程、共享依赖或名称相近自动加入选集。
- 状态同时显示批次总览和逐 Mod／实际组结果；仅部分成员完成时显示部分完成，不能把任一成功提升为整批成功。
  攻击、保护、来源、存储、客户端、Native／Host 均使用这个集合范围，不只方法全返回支持多选。


- 整 Mod 内的多个实体、物品、方块实体、工厂、共享状态、回调和辅助类统一纳入目标。
- 同文件或同模块承载多个 modid 时，以不可分割的实际执行载体为作用组，输出全部受影响 modid。
  该组在开始效果前即确定；不能显示只选一个 modid，实际却秘密停掉多个模块。
- 多 Mod 共用同一个 ClassLoader 不代表它们属于同一目标，不能按 ClassLoader 整体清空。
- 外部依赖库及框架保留公共实现；阻断目标 Mod 的调用、委托和已确认份额。
  只有实际证明专属且进入本次作用组的载体才整份处理，依赖关系不自动授权处置无关 Mod。
- 动态 helper、代理、lambda、隐藏类、独立加载器和 JNI 输出沿实际定义／委托记录继承归属。
  未确认来源列出缺口，不通过猜测扩大到全 JVM。

本次授权覆盖选定 Mod 的共同功能，不等于停掉操作系统、全局安全组件或所有玩家客户端。
授权范围外的 Mod、共享框架、存档记录和连接保持运行。

### 1.2 三条完整链

1. **整 Mod 攻击**：公布整组停用策略 → 封方法／回调／任务／发布 → 清存量身体与登记 →
   处置整组恢复源、资源和持久记录 → 跨重启维持终结结果。
2. **整 Mod 防御**：保护 Ronova 自身整条控制链及用户指定的被保护 Mod → 在实际写入、拆除、
   返回和发布入口拒绝非法效果 → 对已授权反制的来源 Mod 执行整组停用。
3. **持续控制**：游戏 JVM 创建前启动引导并准备规则 → 应用 main／目标效果前建立实际控制 → 覆盖后续定义和派生 → 维持截点 →
   处理旧活栈与原生路径，明确未控部分。

自动反制只采用当前策略已授权的来源 Mod 集合；观察到调用栈名字不等于取得整份反制权限。
被保护 Mod 不自动取得篡改 Ronova、绕过指令来源或影响其他保护组的资格。

### 1.3 各方面统一按整 Mod 设计

| 方面 | 整份 Mod 的目标效果 |
| --- | --- |
| 实体、物品、方块实体、世界作用 | 该组全部已归属对象和登记处理；同 Mod 邻居不再作为保留对象 |
| 方法、分派、返回 | 静态／实例／私有／合成方法和覆写入口统一受控；所有声明返回类型纳入，不能只靠方法名白名单 |
| 字段、容器与引用 | 同 Mod 共用开关、集合、缓存和引用一起停用／清理；混合容器处理整组条目 |
| 事件与任务 | 整组订阅者、队列、定时／周期／ForkJoin／CF 后继拒绝新效力；专属调度器退役 |
| 重建和持久来源 | 整组 holder、工厂、标量、SavedData、外部已登记保存源共同处置 |
| 客户端和通信 | 该组镜像、renderer、HUD、界面、输入、包处理和纯呈现统一限制并收尾 |
| 自保和反制 | 保护整组代码、桥、策略、对象和关键资源；已授权攻击源按整个 Mod 反制 |
| 错误隔离 | 已归属且触发整组隔离策略的故障停用整份来源 Mod，保持外部游戏循环前进 |
| Native／Host | 按实际属于该作用组的环境、映像、回调、私有线程／进程及资源实施控制 |
| 完成结果 | 分别报告整组执行压制、存量清理、来源终结、持久接续；不以方法返回正常代替效果 |

Pro 不增加兼容、强化、极限强度档。保留的单对象原语用于实现整组动作和既有明确单对象命令，
不得用单对象通过冒充默认整 Mod 方案完成。直接执行、低体积和先写完整代码再集中验证继续适用。

## 2. 当前基线：保留什么，补什么

当前已交付实现基线是 build25、Core／Agent／Bootstrap ABI 25。下述 R8 是原始历史起点；
本修订不改变任何产物或持久版本。既有 A 的通过范围保留，新整 Mod 扩展登记为待实现。

本版初稿基线为 R8：MC 1.20.1、Forge 47.4.23、Temurin Java 17.0.15+6、Windows x64。
R8 当时 Core/Agent/Bootstrap ABI 18，Storage Native ABI 2；当前实现版本以 A 批状态为准。
设计补订不自动改变 ABI 或任何持久格式，也不把历史基线写成最新候选。

| 当前已有资产 | 本版处理 |
| --- | --- |
| ProRuntime 请求内清体、即时策略、代次和交接 | 继续作为唯一编排入口，调整真实动作，避免再套调度/许可层 |
| EntityRecords / BackingPolicy / Access | 复用原字段与准确登记操作，扩大真实承载结构覆盖 |
| R8 有效生命、alive/dead 与客户端保护 | 保留已修路径，扩展尚未覆盖的实际 writer/返回通道 |
| SourceMaps / RecoverySources / RecoveryReferences | 复用现有来源模型和容器操作，补直接字段、标量与 BlockEntity 生产关系 |
| TaskBridge / RecoveryTasks | 复用 invocation、拒绝启动、结果发布、退出、后继和资源工作 |
| RecoveryAgent / 各 Boundary / NativeControl | 复用当前变换链和 bootstrap 桥，补入口维护及明确的底层后端 |
| BlockRecords / ClientPresence / ProNetwork | 延伸方块实体、客户端与网络的实际路径，不用 Entity 逻辑冒充所有载体 |
| IntentJournal / RecoveryStorage / StorageNative | 保留持久原意图、提交与重启接续，完成剩余生产路径 |

R8 的历史定向结果和 build25 的原 A 结果各保留原范围；它们没有覆盖新整 Mod 攻防、完整持久链和 Host。
特别保留两项接续事实：

- 普通安装防护回归走免手填参数入口；完整启动捕获的恢复链回归使用了提前安装入口。
  两种结果不能合并成“普通晚附加已覆盖全部启动前历史”。
- 停服仍有 `INLINE_RETIREMENT_EXIT_OR_CAPTURE_PENDING` 未结项，
  具体身份与日志保留在 R8 报告，进程正常退出没有清偿它。

本版没有因研究报告发现新机制，就把 R8 已完成的代码重新登记成“未写”。
已写、局部已验、缺少执行路径、尚待整体验收分别记录。

## 3. 直接执行规则

### 3.1 整组普通内存动作的最短路径

用户请求 → 定位实际 Mod 作用组 → 一次发布当前组策略 → 已知方法／写入／发布立即受控 →
批量处理该组现有对象、任务和登记 → 后置汇总结果，继续推进来源和持久工作。

全组默认采用 6.7 的枚举即处置规则：所有实际可执行成员直接动作，不仅限最初对象。
组策略复用现有操作身份与当前代次。每个字段、任务、方法只读当前组状态，不各发一张许可、
不逐动作写日志、不为每个实体重新建一套完整流程。新归属载体沿实际登记事件加入同组。
未枚举完的部分继续推进，已知部分无需等待全图、全 JVM 扫描或刷盘 ACK。

选中组自己的共享开关、缓存和方法可以整份停用；外部共享框架中的目标份额仍按实际位置操作。
保留对象身份、当前槽位、方法描述符和策略代次这些会影响实际执行的必要判断。
同一请求跨多个对象和类，不自动升级成逐对象持久许可。

同内容不同加载器、旧定义残留、覆盖变更只在作用组建立及真实变化时处理。
直接内存动作继续即时执行，不等存储、未知回调或尚不可用的 Native 后端。

### 3.2 只让有外部后果的步骤等待

以下步骤沿用一份现有持久原意图：写盘/事务提交、跨重启策略、Host 处置，
以及不能安全重复且效果未知的回调或资源释放。
需要时先持久化、再在最终效果点复核，随后独立查询结果。

组合操作逐步分流：保存正在等待，不挡准确内存清体；未知死亡回调不挡索引移除；
缺某个 Native 后端，不停掉已经可用的 Java 攻防。
已执行但结果未知的步骤沿原 key/attempt 查询，不能换身份再试一次。

最终效果与撤销由同一个短定序点决定先后。准备、扫描、大块 I/O 和第三方回调放在门外；
不会为了“证明还有效”把锁持有时间拉长。

### 3.3 三条削减规则

- 同一当前绑定的重复解析、同版本重复哈希、无变化的全量扫描，合并或删掉。
- 仅用于打印“存在/已安装”的生产探针不进入每次攻击；开发检查留在独立夹具或按需诊断。
- 每个新增组件必须提供一个原来没有的执行入口、受控后端或必要的共享适配。
  单独包装一个布尔值、场景编号、检查结果不构成新增组件的理由。

### 3.4 策略修改入口不能借道解除攻防

`clear/protect/revoke/cancel` 及停用、重置、玩家交接等能改变当前策略的入口，
必须绑定真实命令请求或本方已建立的内部生命周期操作。
服务器线程、方法为 public、同包名、传入一个 owner 或来源 ID，都不单独构成修改资格。
外部代码借 ProRuntime 的合法方法执行，也不能因此成为本方受信写入。

复用现有准确运行时、目标、操作/代次及短生命周期上下文，
在真实策略修改点拒绝未授权的解除、取消，以及借 protect 重置终结状态。
上下文由实际入口建立，只覆盖该次动作；不能跨目标、跨线程或被第三方回调继承。
合法玩家命令、退出、换身与撤销仍可执行；不为普通内存动作新增刷盘 ACK 或通用许可证。

### 3.5 策略判断与实际内存效果共同定序

跨线程关键写入不能只有“查询允许 → 返回布尔值 → 无条件写入”。
保护激活、撤销、代次变化和载体交接，必须与实际写入/发布在共同短定序点决定先后。
旧绑定或旧代次的允许结果不能用于新载体；先发生的真实效果也不能事后冒充被阻止。

按实际入口复用拥有者线程、短锁或带预期值/代次的 CAS；
共同保护范围须覆盖真正的存储或发布，不能只锁住查询方法或再加一次前置检查。
第三方回调、扫描与大块 I/O 留在门外；无法在高层定序的操作下沉到准确效果点，
不把整个游戏线程冻结来换取防护。适用的单线程动作保持最短直接路径。

## 4. 通用攻击：整份 Mod 的执行与存量一起处理

### 4.1 从目标 Mod 开始，不逐怪启动一套攻击

一次操作复用 ProRuntime 为选定的多个 Mod 建立批次及各实际组策略。先捕获真实登记和必要收尾信息，再启用停用规则；
快照捕获与策略发布以当前版本衔接，变化载体回到待处理队列，不依靠长时间冻结世界。

1. 封目标组已知的方法进入、委托执行、重排、创建结果、事件及发布入口。
2. 已执行旧调用继续受真实写入／发布点限制；无法覆盖的在途执行单独报告。
3. 批量处理目标组全部实体、物品作用、BlockEntity、ticker、索引、Tracking、关系与客户端存在。
4. 停用整组工厂、活动开关、持有集合、回填回调；剪断组内和外部容器中的目标组份额。
5. 退役专属调度器与资源，完成存储处置及重启后的组策略接续。

运行期第一次枚举当前载体是执行所需工作，后续沿新注册／派生／定义变化增量处理。
不每 tick 重新扫描所有方法、所有堆对象或全部文件。

### 4.2 身体、登记与世界对象

EntityRecords 继续处理真实字段、ID／UUID 别名、Lookup、Section 全表／分类表、
Tick 活动／备用／迭代表、Tracking、乘客／载具、Multipart、导航及 callback。
批处理包含同 Mod 的其他实体；不再以“不是最初选中的 UUID”为由保留该组活跃对象。

清登记先使用原真实位置和标识。不得先随机 UUID、写 NaN 或把查询改成 -1 后再尝试找原槽位。
目标覆写的 remove／getHealth／isRemoved 不能否决底层清理；Opaque 死亡和掉落语义单列。
清体和方法停用要避免互锁：Ronova 所需收尾不借道执行任意目标回调，未知回调不阻塞独立结构步骤。

BlockEntity、物品／装备、方块／区块作用和纯呈现各走对应原语，不能用 Entity.remove 统一冒充。
方法被截断后，Minecraft 仍持有目标对象时可能继续调用它；必须清存量登记或在调用边界维持合法合同。
世界索引的普通查询保持真实，不能通过隐藏 /say 或 /forge 输出显示成功。

### 4.3 组内来源全部纳入

| 来源形态 | 整 Mod 动作 | 复用落点 |
| --- | --- | --- |
| 静态和实例字段 | 目标组所有已确认 holder、直接引用及重建状态一起停用／断开 | RecoverySources／RecoveryReferences |
| Map／List／Set／数组／包装 | 专属容器整组处置；混合容器删除所有属于目标组的条目 | SourceMaps／BackingBridge |
| 标量／计时器／生成配置 | 专属生产开关可以整份关闭，不再要求保留同 Mod 的其他生产对象 | CreationBoundary／TaskBridge |
| 工厂／helper／任务输出 | 沿实际输入、定义、委托与输出继承组归属，拒绝换 UUID 和无 NBT 重建 | RecoverySources／RecoveryTasks |
| BlockEntity／核心 ticker | 整组核心与生产登记处置，拒绝它继续替换／注册新 ticker | BlockRecords／实际登记入口 |
| SavedData／文件来源 | 组内存量记录和后续保存统一受控，持久提交仍按文件真实身份执行 | RecoveryRecords／RecoveryStorage |
| 独立循环／迟到后继 | 拒绝后续外部效力及派生；无法控制的旧活栈保留明确范围 | DispatchBoundary／TaskBridge／Native |

### 4.4 来源范围与容量

类定义在目标模块中的对象可直接采用当前整组策略，不能再要求每个新 UUID 先证明属于某个旧实体。
目标在外部通用库中创建的对象按真实创建／委托来源关联；没有关系记录时不凭同线程或相近时间猜归属。
同名不同加载器、共享库、JDK/Forge 全局对象均不得仅凭名字加入作用组。

捕获溢出保留整组已生效停用策略，继续关闭已经确认的发布入口；调度恢复后补处理新增载体。
不丢弃整组禁入，也不把没观察到的对象都判成目标。采用依赖变化、有界批次与公平轮转。

### 4.5 压制和来源终结分开

整组入口不断拒绝旧源重建属于持续压制；真实来源、任务、资源和保存处置完才属于来源终结。
测试和输出按整组聚合：一只怪消失、一个方法全返回或一个工厂被停均不足以表示整 Mod 完成。

## 5. 通用防御：整 Mod 状态、结构、代码和镜像一起保护

保护默认覆盖 Ronova 自身全部执行链与关键资源；用户指定被保护 Mod 时，同组对象、登记、
静态状态、代码、任务、存储与客户端作用点一起进入保护策略，新归属对象自动继承。
不需要玩家逐个实体执行 protect。保护合法业务的调用合同，禁止非法移除和覆盖；
不能把全部方法返回 true 或所有 setter 禁用当作完整防护。

### 5.1 激活后立即起作用

保护请求直接发布现有当前策略；工作线程和服务器线程读同一份有效状态。
判断已绑定对象是否受保护，不依赖可能被破坏的 raw level、UUID 或目标 getter 再找一遍 runtime。
后台观察队列、日志延迟与完整来源图不能成为放行非法写入的理由。

防住已知受保护对象，不需要先识别攻击者所属 Mod。
先在准确写入/消费点拒绝，随后再追实际 writer 与上游执行源。

### 5.2 五个作用面

| 作用面 | 本版要求 |
| --- | --- |
| 有效生命与状态 | 延伸 R8 的 getHealth/isAlive/isDeadOrDying 控制；同时守原生命、最大生命、DataItem、死亡/移除状态、更新资格、效果、火焰、饥饿与装备 |
| 物理承载结构 | 守 ID/UUID、Section/Tick/Tracking、callback、位置/包围盒、关系与适用多部件；实体能真实 tick、移动和被跟踪 |
| 直接修改入口 | 实际生效覆写、PUTFIELD/PUTSTATIC、反射、句柄、Unsafe/CAS、集合视图和迭代器；按具体对象、字段类型和操作语义适配 |
| 上层替换 | manager、lookup、集合、数据项或 callback 发布前拒绝非法替换；合法迁移更新当前绑定 |
| 客户端存在 | 保护合法镜像、当前连接/代次、HUD/BossBar、准确 draw 份额与必要输入；合法包和同批其他对象照常处理 |

基本类型字段和对象引用字段分开处理；不能把 `Float` 引用槽当成 `float` 写。
共享集合操作在实际 mutation 处保护被保护 Mod 的全部份额；保留外部 Mod 的条目、迭代进度与回调异常语义。

#### 构造期、静态初始化与辅助加载器

字段/数组写入覆盖不能整段跳过 `<init>`、`<clinit>`：
构造方法中未初始化的 this 与已经存在的外部对象分开处理，
在符合字节码初始化规则的位置保护真实外部写入；静态初始化中的外部效果同样受控。
不能因为构造自身的写入需要特殊处理，就放行整段方法的其他修改。

Minecraft/Forge 包名、模块内 `mods.toml` 或研究样本名字不是完整的 writer 覆盖边界。
辅助加载器、动态定义及不携带 Mod 描述文件的实际写入代码，按真实定义/加载器和操作接入。
字段声明解析不能只依赖加载器返回的 class 资源；资源缺失或与实际定义不符时，
接续真实定义元数据或另一有效效果截点，不能静默跳过再声称该字段受保护。
复用现有 Boundary 和最终容器/发布控制，不为每种加载器复制一套框架。

### 5.3 前置阻止和受损修复分别报告

常态要求是非法状态没有进入真实原值、登记或外部发布。
R8 的有效生命返回控制作为其中一条通道保留，同时处理对应原状态；
仅让 getter 回答“活着”不能代替物理存在和真实保护。

后置修复用于防线已经被突破时的恢复：重新定位当前容器，补回当前合法身体和必要状态，
清理旧快照引用；记录真实损失，不覆盖后来合法的位置、装备和世界变化。
死后复活、移除后回插、坏包后重同步，都按修复报告。

合法传送、末地返回、重生、换身、资源重载和解除保护走已有交接路径；
保护不靠永久复活旧对象，也不靠冻结玩家和共享服务器维持。

### 5.4 攻击源处置也按 Mod 聚合

已授权整组反制的来源一旦命中实际非法效果入口，复用同一个 mod-stop 操作封住该组后续效力。
不能只修复被打掉的一个字段，再放任同组其他 writer、任务或回调继续攻击。
先挡当前非法效果，来源解析和批量退役在门外推进；误报来源不得导致公共 Forge／JDK 被整份停用。
合法玩家退出、换身、传送、存档和资源重载通过原有交接路径，不因整组防护永久冻结。

## 6. 自己的控制链必须持续有效

### 6.1 游戏 JVM 启动前开始，由启动引导交接进程内控制

用户进一步明确要求“启动前就开始”。本设计按游戏 JVM 进程创建前启动 Ronova 引导组件处理，
不再仅以进入世界前、Forge 初始化前或 Mod 构造前作为该要求的完成时点。
本条修订取代此前“只把 JAR 放进 mods 就能独立实现游戏进程启动前控制”的交付假设。

#### 启动前和进程内是连续的两个实际阶段

| 时点 | Ronova 执行什么 | 完成口径 |
| --- | --- | --- |
| 用户触发已接入的游戏启动入口，游戏 JVM 尚未创建 | 引导组件读取本次自保、已保存多 Mod 目标集合、原停用意图和所需载荷；准备实际启动参数与来源候选 | 引导和规则准备已开始，此时不存在的 Java 方法不能声称已经被改写 |
| 创建游戏 JVM，进入应用 main 之前 | 以实际启动参数加载 Agent／bootstrap 及必要后端，安装自保、定义／调用／写入入口并接入本次规则 | 对已安装入口开始实际控制；不能把 premain 写成发生在 JVM 进程创建之前 |
| Forge／ModLauncher 发现、目标类定义与初始化 | 以真实文件／定义／加载上下文定位目标组，在初始化／创建／注册／任务首次执行／发布前实施策略 | 目标实际效果被前置拒绝；先执行了再补回不算前置成功 |
| 世界和客户端运行 | 整组遍历全返回、增量纳入、存量清理、来源与资源退役、客户端控制和持久接续 | 保持控制并报告各组真实结果，不要求玩家再次激活 |

支持的启动器通过正式前置启动接点调用引导组件；无可用接点时提供轻量的 Ronova 启动入口，
由该入口启动用户选定的游戏实例。复用现有启动器配置和发行载荷，不必另做一整套账户／下载启动器。
首次接入需要实际配置启动链；接入后玩家正常点击启动即可，仍然免手填 JVM 参数。
引导组件自动提供必要的 Agent／模块参数，保留原 Java 版本、内存、游戏目录和用户合法启动设置。

单独放入 mods 的 JAR 无法在其所属游戏 JVM 尚不存在时自行执行。
未经过受支持前置入口、绕过引导或在游戏已经启动后才安装时，明确显示前置未接入／运行期接续，
不得通过晚附加 INSTALLED、更高优先级数字或一个“引导已启动”日志显示完整前置已生效。
本设计不要求未获授权的系统开机常驻、改写其他启动器程序、UAC 绕过或隐式安装内核驱动。

启动策略的定位首先使用发现阶段实际来源；不能为了获取 Mod 对象而主动执行目标构造或静态初始化。
目标稍后出现时在实际定义／效果边界增量绑定，不等完整 ModList 和世界创建后再决定。
组内所有已归属新类、helper、任务和输出继承当前策略；目标组未全部枚举完不妨碍已知入口先控制。
0 延迟回调和工作线程直接读取当前规则，不能等待服务器下一 tick 才作本应前置的拒绝。

自身防护默认启动；已保存的多 Mod 规则自动接续；尚未选择的攻击集合为空，不猜测要停用哪些 Mod。
界面、武器面板和指令只负责配置／保存规则、改变运行期选集与查看结果，不是每次启动防护的触发器。
游戏运行后新增目标立即限制后续效果并处理存量，但此前历史不能追回；下次启动规则和本次接续分别显示。
远端服务器会话规则不会自动取得本机启动前控制权，只有用户授权保存的本地启动规则进入这条启动链。

现有 SelfBootstrap 晚附加仍可接续旧会话，但不满足这一新的启动前要求。
多 Agent／Native 和更早宿主组件按实际顺序与依赖处理，不能保证一个 Java Agent 先于所有原生代码。
所选平台无法兑现的必要前置路径明确未完成；需要更底层截点时实现真实依赖，不能改成只监控就算完成。
Agent 必须在真实入口建立后才报告该入口可用；引导与安装失败保留具体阶段，不自动启动一个假定受保护的实例。

Java premain 的实际时序是 JVM 初始化后、应用 main 前，见
[Java 17 Agent 启动规范](https://docs.oracle.com/en/java/javase/17/docs/api/java.instrument/java/lang/instrument/package-summary.html)。

### 6.2 实际维护，不反复扫描

- 注册关键入口与当前定义/加载器的真实关联；框架回调、定义变化和明确异常触发定点维护。
- 对本方变换器、桥接 receiver、准确分派和关键资源，分别找到真实拆除/替换入口。
- 覆写/变换后继续按实际方法副作用控制，不只比较 JAR 资源字节或检查类是否存在。
- 缓存按实际类、加载器和版本组织；同名类不合并，退役定义和无使用者快照可释放。
- 保留低频、有界的完整性补查作为漏观察兜底，不每 tick 全量 retransform。

新门准备好后再交接；旧门失效期间若其他已安装截点仍能阻止效果，继续用它。
若确实出现缺口，则准确报告受影响能力并修复，不用“正在恢复”冒充全程防住。

重转换不会改变已经执行中的旧栈帧，所以在途调用后续的实际写入/发布边界必须仍受控制。
这也是本版优先补最终效果点的原因。
[Java 17 Instrumentation](https://docs.oracle.com/en/java/javase/17/docs/api/java.instrument/java/lang/instrument/Instrumentation.html#retransformClasses(java.lang.Class...))。

### 6.2.1 字节码变换控制链的防拆

将 Java 转换器管理、Native 回调和最终类定义作为相连但独立的控制面。
`ClassFileLoadHook` 是 JVMTI 类文件回调；`TransformerManager` 是所选 JDK 的内部实现，
不能把名称或内部布局写成所有 JVM 通用合同。

- **Java 注册与分派**：保护本方准确转换器的移除、替换、注册顺序及实际分派入口；
  后续重新定义/转换仍保留当前攻防入口，无关转换器与合法类加载继续工作。
- **Native 回调与桥接**：所选后端应阻止本方实际 JVMTI 环境、事件启用状态、回调注册及
  libinstrument 相关调用链被非法取消、替换或截断。跟踪准确环境和实际执行关系，
  不把关闭单个环境的事件解释成关闭全局所有 Agent。目标组自身的 Agent／Native 环境进入该组处置；组外 Agent 不因同处一个 JVM 而自动停用。
- **最终定义与交接**：考虑后续 Java/Native 转换覆盖本方输出的路径；准备好新入口再交接。
  停止未来 transform 不会自动撤销已有改写，已有代码仍在也不能证明未来类加载继续受控；
  旧活栈与最终写入/发布点继续按 6.2 的合同处理。
- **实际缺口**：某条路径无法阻止时，明确受影响入口和定义范围；后置发现与重装不冒充前置防住。
  DLL 加载、hook 名称存在和 INSTALLED_FULL 均不能单独证明 Native 控制链完好。

实施复用现有 RecoveryAgent、ControlBridge、ControlImages 与 Native 控制后端。
Java 基础入口防拆归 A；完整 Native/JVMTI 控制面归 C。
A 已声明的基础动作若实际依赖其中某个 Native 截点，该准确依赖随动作前移，不能以阶段归属跳过。
本节补齐设计范围，不代表新增实现已完成或已有 PASS。

必要检查并入既有“控制链与普通安装”组：以自有夹具制造准确入口拆除或后续改写，
观察下一次真实类加载/重转换及攻防动作，同时检查既有定义、旧活栈与无关转换器的行为。
不另建周期性全量扫描、逐动作证明层或新的能力证书体系。

[Java 17 ClassFileTransformer](https://docs.oracle.com/en/java/javase/17/docs/api/java.instrument/java/lang/instrument/ClassFileTransformer.html)
与 [JVMTI ClassFileLoadHook](https://docs.oracle.com/en/java/javase/17/docs/specs/jvmti.html#ClassFileLoadHook)
给出变换链及环境语义；后端必须按实际 JVM 版本实现。

### 6.2.2 安装失败必须处理实际覆盖

Java `ClassFileTransformer` 抛出异常不会自动阻止类加载、重新定义或重新转换；
JVM 仍会尝试后续变换和定义。因此解析、控制对象捕获、图像保存或桥接失败，
不能只靠抛异常实现拒绝，也不能被错误隔离改写成普通成功。

失败立即影响对应定义和调用入口的覆盖状态，安装时缓存的成功值不得继续代表当前有效。
保留已经有效的守卫，通过独立消费/写入/发布截点阻止受影响调用对已知目标取得非法效力；
无法做到时该能力明确未完成并修复实际执行入口，不能以日志代替阻断。
无关类加载、合法任务与游戏循环继续；不通过全局拒绝加载或吞异常冒充可玩性。

关键控制登记的容量与普通观察数据分别管理，在用入口不能因新增观察而被淘汰。
异常、容量和重试均有界，失败恢复按实际定义变化定点进行，不每 tick 全量重装。
平台语义见本章的 Java 17 ClassFileTransformer 官方说明。

### 6.2.3 首次接管、图像基线与共同失效点

首次观察到的字节、磁盘原始 class、当前已执行定义与可信控制基线分别识别。
ControlImages 缓存第一份输入不能直接证明该输入未被其他变换器修改；
首次接管需建立本方关键入口的真实控制，并保留合法 Forge/Mixin 处理。
已有异常定义、无法接管的入口与附加前旧活栈分别处置，不能把缓存重放等同于完整恢复。
图像保留、定义交接继续绑定真实类、加载器和版本；不靠每次动作重算全量哈希。

明确每个关键效果截点所依赖的注册、桥接、策略存储和 Native 后端。
多个守卫若依赖同一变换链，不按多个独立防线计算。
主链受损时，仍有效的实际写入/发布截点应继续守住已知目标，再进行定点接管；
若备用截点也依赖已损坏入口，则它不是有效接替路径，须补真实独立后端。
Java 管理器修复不代表 Native ClassFileLoadHook/libinstrument 链已恢复。

### 6.3 整组代码处置保持通用

借鉴提前加载、入口短路、全部返回出口改写、补丁幂等和定义交接，复用现有转换器与桥。
本修订明确允许清空／短路目标 Mod 的方法、订阅者和功能；不再受旧版“同 Mod 方法不能整份停用”限制。
按用户选中的真实作用组执行，不按特定 Boss 名称或固定第三方包名定制战斗名单。

全局 EventBus、JDK、Forge 和共享加载器保留公共功能，只拆其中目标组的登记或效果。
Mixin／ASM 已把目标逻辑合入 Minecraft 类时，按实际注入来源和定义变换记录处理该部分，
不能因为载体叫 Minecraft 就漏掉它，也不能反过来清空整份 Minecraft。
来源已丢失的混合方法保留未控状态并在调用／效果点限制，完整定义接管归 C。
原始字节、Forge/Mixin 合法定义和当前受控定义区分，不能盲目整类回写磁盘 class。

### 6.4 Native 与 Host 的推进

Native 控制、Native 存储、Host 权限/驱动是不同后端，分别复用和推进。
DLL 加载成功只代表加载步骤，接口还必须和 Java 声明、ABI、加载器及实际调用匹配。
未接上的导出和占位函数不计入能力。

必要的 Java native 绑定控制可跟随 A 的实际依赖前移。
NativeMethodBind 可在该方法绑定时提供替换地址，但它不覆盖任意本机内存写入。
[JVM TI NativeMethodBind](https://docs.oracle.com/en/java/javase/17/docs/specs/jvmti.html#NativeMethodBind)。

完整 C 阶段继续保留以下最高目标：

| Host 能力 | 要落实的实际效果 |
| --- | --- |
| 自动提权 / Privileged Execution | 自动请求或复用已授权高权限，执行需要该权限的实际动作；同时显示真实权限和失败原因 |
| 使用/安装内核驱动 | 支持的签名组件安装、加载、升级、卸载和交接；拥有能执行所需控制的后端 |
| 模块与注入控制 | 对授权目标的实际加载、绑定、准入或已进入模块作对应处置；通知与拒绝分开 |
| 进程/子进程/线程 | 对明确目标关系执行创建限制、控制、保护与退出处理；共享系统对象不连带 |
| 文件/资源访问 | 读、写、执行权限和适用 I/O 的实际控制，保留必要原状态与查询接续 |
| 常驻与恢复 | 可管理的存活、异常恢复、受控重启/终止与未结工作交接，保持单一游戏 writer |

目标不降成“仅提示/仅监控”。系统授权、签名和平台支持按真实条件实现，
不把绕过授权、破坏无关系统组件或不可卸载当作强度。
能力确实选用时再实现安装和生命周期，不提前搭一套没有生产用途的平台工程。

### 6.5 全方法、全返回与实际分派

停用组必须枚举当前已定义类及后续类加载，覆盖普通静态／实例／私有／bridge／synthetic 方法、
实际覆写和默认接口实现。控制归属绑定真实定义与模块；框架继承方法按接收者／调用来源限制，
不能把修改目标类已声明方法等同于覆盖所有继承调用。

入口参考至少包含 tick／baseTick／AI、移动／传送、攻击／射击、治疗／状态、创建／工厂、
事件回调、任务和后继、注册／发布与保存。清单用于查漏，不成为只允许处理这些名字的白名单。

| 方法形态 | 停用动作和返回合同 |
| --- | --- |
| void 动作 | 在实际业务入口短路，目标主体不执行；只保留必要框架／资源收尾 |
| 布尔、整数、浮点及其他基本类型 | 按描述符生成合法直接返回指令；默认整组全返回，固定值及专用策略见 6.6 |
| 对象／数组返回 | 支持整组强制 null、类型正确空结果及专用返回策略；外部消费与收尾见 6.6 |
| 所有 return 出口 | 覆盖所有分支返回，处理返回槽宽；入口控制负责阻止此前副作用，出口负责控制结果 |
| 构造方法 | 在实际创建入口或合法异常路径拒绝新建；不生成缺少必要 super 初始化的半对象 |
| 静态初始化 | 封新类产生目标效力，处置现有注册与缓存；不以半初始化类继续正常游戏 |
| abstract／继承方法 | 处理真正有方法体的实现或外部调用边界；不向 abstract 方法硬塞返回 |
| native／隐藏类／不可修改类 | 采用可用的实际绑定／委托／调用截点；没有后端时单列未控数量和位置 |
| 已经执行的旧栈帧 | 新方法体不会追回旧调用；继续控制写入／发布／后继，实际退出后再结清 |

生命查询、无敌查询、Tick 停用、清登记、停伤害、停死亡回调分别属于不同语义。
不能把截图中 isInvulnerable=true、hurt=false、remove 短路混为一种清除效果；
攻击和防御分别使用停用／保护语义表，表只驱动现有后端，不为每个名字建一个类。

补丁按目标组、实际定义、方法描述符和当前代次去重与组合；局部失败不吞掉其他有效动作。
撤销需按当前基线重算保留其他生效补丁；unregister 或 retransform 本身不表示恢复原样。
共享同步方法还需处理调用前获取的 monitor；截断 synchronized 方法体不能终止一个已卡在 monitor 的调用。
不关闭全部 JVMTI／Instrumentation 作为默认前提，不把缺少 Native 支持写成 Java 已全控。

### 6.6 整组遍历全返回、标识扰动和强制空返回

用户明确要求“遍历全返回”。主动作是遍历目标 Mod 的实际类和方法，
对所有适用方法在入口直接返回，原业务方法体不执行；不逐个手写方法名名单，
不轮流枚举数值碰运气。同 Mod 其他对象、公共方法和功能一起失效属于授权效果。

一次枚举该作用组已经定义的类／方法，批量应用当前全返回策略；
后续类加载、重新定义和真实 helper／代理派生沿实际发布入口增量接入。
静态、实例、私有、合成、桥接和覆写方法全部纳入；继承方法按真实实现／目标接收者控制。
共享 ClassLoader 中的其他 Mod 不因加载器相同而并入。

默认在方法入口生成合法返回值和返回指令，跳过原业务主体。
“扫描已有 return 并改值”保留为出口控制动作，它仍会执行方法体此前逻辑，不能冒充入口全返回。
已执行旧栈帧继续由实际写入／发布／后继截点限制；换掉方法体不等于终止旧调用。

| 返回类型 | 整组全返回默认输出 |
| --- | --- |
| void | 直接 RETURN |
| boolean | false，或明确选定的固定布尔策略 |
| byte／short／char／int | 0；特定标识查询可选择类型允许的 -1 等固定值 |
| long | 0L |
| float／double | 0.0f／0.0d |
| 对象／数组 | null；外部接口需要时提供类型正确的停用结果 |

同一方法的所有返回分支采用当前同一策略代次。布尔即便由整数返回指令承载，也按描述符处理。
“遍历”指类、方法和返回出口覆盖，不是自动轮试 false／true／NaN，也不是制造所有数值组合。
构造方法不空返回半对象，在实际创建入口或合法异常路径拒绝新建；静态初始化按真实发布和登记控制。
abstract 定位真正实现；native／隐藏类／不可修改类接可用的真实后端，无后端的路径列为未控，不能静默跳过后报全控。

#### 随机 UUID 与标识扰动

允许对整组适用查询采用固定随机 UUID、按次变化 UUID／字符串、固定失效整数 ID 等专用策略。
固定随机值和按次变化分别声明，属于已选攻击动作，不作为数值轮试。
查询伪装与真实字段重写分开：改变 getter 不会自动解除实体、容器和 Tracking 的实际登记。

先捕获真实字段、原标识、别名、索引、位置和原意图绑定，解除目标登记或共同完成相关槽位交接，
再实施真实标识重写。后续收尾使用原实际引用和登记，不按随机 getter 再找对象。
扰动值不能成为 Ronova 持久工作身份，也不能写成组外对象的合法身份。

#### 批量强制 null

允许目标组引用返回方法统一返回 null，包括让该 Mod 内部调用链不能继续。
void 和基本类型保持合法指令，不能给基本类型塞 null 或伪造初始化完成的构造结果。
目标内部失效进入整组停用／隔离；存量目标对象仍被外部框架调用时，解除登记／引用，
或在对应消费入口维持合法停用合同及资源收尾。Future 必须能取消或完成，不能永久挂起。

不把整个 Minecraft 崩溃、服务端退出或组外 Mod 损坏计为目标停用成功。
这一边界不新增逐方法许可；撤销改写只影响后续调用，不假装复原已发生的初始化、资源或存档效果。
复用现有 DispatchBoundary、RecoveryAgent、TaskBridge 和组策略，不为每个返回类型或方法另建框架。

### 6.7 所有控制面统一采用“能枚举就整组处置”

这是所有后续实现的默认执行规则，不只适用于全返回。对已选 Mod 的真实成员，
凡有可枚举入口和实际动作，就整组纳入并执行；不退回只处理命中实体、只列几个方法名或只观察不动作。
已经得到可执行对象就立即处理，不能等整个组、来源图或持久链全部枚举完再开始。
大集合在共同组策略已生效的条件下分批推进，避免单次遍历冻结游戏；分批不缩减成员范围。

| 可枚举作用面 | 默认全量动作 | 实际执行落点 |
| --- | --- | --- |
| 类、方法、覆写、当前定义 | 全返回／声明返回策略、限制新定义和后续重新注册；混入外部类的逻辑按实际来源处理 | RecoveryAgent、各 Boundary、ControlImages |
| 静态／实例字段与引用 | 批量断开目标恢复引用、停组内开关、覆盖已选字段状态；身份和框架关键状态先保留收尾依据 | 字段／反射／句柄／Unsafe 的真实写入入口 |
| 容器、数组、缓存、别名、对象图 | 目标组专属容器可整份清理；混合容器删除全部目标组成员，清已确认深层别名 | SourceMaps、RecoveryReferences、BackingBridge |
| 实体、BlockEntity、ticker、物品作用、世界登记 | 批量清该组全部当前对象、索引、关系、Tracking 和适用世界登记 | EntityRecords、BlockRecords、实际世界拥有者 |
| 事件、监听器、命令、服务与工厂注册 | 全量取消目标组登记并阻止重新注册；框架共享分派继续 | EventBus／注册／委托与创建入口 |
| 普通任务、Future、定时／周期、ForkJoin、CF | 全组拒绝启动／派生／发布、取消队列份额、结算真实退出和全部后继 | TaskBridge、RecoveryTasks、现有 JDK 入口 |
| 私有池、线程、调度器、等待者 | 已确认专属执行器整体退役；共享执行器中只退役目标组份额；等待者可结束 | 实际 executor／scheduler／waiter 关系 |
| holder、标量、SavedData、独立重建源 | 整组停生产、断持有、处置活动开关／保存记录，纳入换 UUID 和无 NBT 输出 | RecoverySources、RecoveryRecords、CreationBoundary |
| 已登记文件、保存任务、存档条目 | 批量封该组非法写入，私有来源按意图处置，混合文件处理全部目标组记录 | RecoveryStorage、真实句柄、提交和重启接续 |
| 客户端实体、renderer、HUD／BossBar、UI／输入、绘制资源 | 整组停止呈现／交互作用并退役实际资源；仅在已授权客户端本地作用组执行 | ClientPresence、客户端实际渲染／输入入口 |
| 网络 channel、handler、目标包与排队输出 | 全组拒绝新效果并处理已排队份额，保留连接和组外正常消息 | ProNetwork、实际处理／序列化／发布边界 |
| Mixin／ASM／Agent／transformer／ClassLoader 注册 | 处理已确认属于目标组的定义和注册，维持自有组控制，不按共享加载器整体清空 | 真实定义链、ControlBridge、后端接管 |
| JNI 绑定、Native 回调／环境／映像、句柄 | 对目标组已登记的全部成员执行支持的绑定限制、回调退役和实际释放；不得擅自卸载仍在执行的共享映像 | NativeControl、所选 Native／Host 后端 |
| 被保护 Mod 的对象、代码、策略、资源 | 全量建立组保护，新成员继承；非法效果即刻拒绝，授权反制源进入同一整组攻击动作 | 当前组策略与同一批效果截点 |
| 已归属的故障、恢复与停用接续 | 整组隔离、必要收尾和当前完成撤销；后续新载体继续处理 | 既有错误隔离和操作／代次调度 |

可枚举不等于可以把所有字段一律写零或对所有句柄调用 free：动作按选定的攻击／保护／退役语义执行。
私有范围可以整份处理；组外共享框架和混合资源的其他份额保留。归属来自实际载体和委托，不靠包名／线程名猜测。
直接内存步骤照常立即执行；需要提交的存储和不可重复 Native 释放仍沿原意图，不能用遍历重复施加未知效果。

枚举顺序采用当前实际登记与载体关系，保存待处理游标；遍历中新增和重新插入项由同一策略和真实注册入口接入。
第三方自定义 iterator／getter／回调可能再次产生效果，优先使用已有 backing 访问和已捕获原始记录，
不能让目标抛异常就终止整组操作，独立可执行项继续。
已有实际枚举支持之外的不可达对象、丢失来源、逃逸 Native 或旧活栈仍列为缺口；
结果要区分“枚举到的已处置”与“目标组全部必要路径已闭合”，不以扫描无新项宣称所有隐藏载体不存在。

以上每一行复用原有职责，按 A/B/C/D 的实际后端完整程度推进。它们是能力范围，
不是新增一份每行必跑测试表。先写完整块代码，再只检查影响真实攻防效果的缺口。

## 7. 错误隔离与可玩性

用户启用整 Mod 错误隔离策略后，故障归属已确认的目标 Mod 进入同一个整组停用流程：
拒绝新回调／任务／包／绘制，移除存量作用并退役资源，不逐次加一个类名黑名单。
已明确手动停用的组，即使没有抛异常也立即处置，不等某个功能再出错才停下。

一次回调异常仍在可恢复边界收尾，公共事件总线、游戏主循环和其他 Mod 继续。
对于目标 API 被短路后仍会被外部调用的情况，清存量引用或提供符合合同的停用结果，
不得用大量 null／空构造把整个游戏拖崩，再声称目标 Mod 已失效。

未知来源的错误按实际影响限制传播，不能直接升级为全 JVM 停用。
必要 finally、Future 完成和资源收尾不被默认吞掉。失败只记简短原因并限频。
初始化／存档失败不映射成普通成功；JVM 崩溃与不可恢复资源耗尽不由 Java catch 假装修复。

## 8. 任务、资源、存储与重启接续

### 8.1 整 Mod 任务与资源退役

TaskBridge／RecoveryTasks 读取当前组策略；全部已归属的普通 Future、定时／周期任务、ForkJoin、
CompletableFuture 回调、后继、独立线程和私有调度器统一加入退役工作。
首次调用和 0 延迟回调在实际入口拒绝，不能等待服务器下一 tick 合并后才决定。

目标组专属线程池／定时器可以整体关闭并阻止重建；共享池继续接收其他 Mod 的任务。
共享队列中的全部目标组份额清理；包装只沿实际委托解析，不用线程名／TCCL 猜定所有权。
目标专属线程可在其可用合同下请求取消／中断；共享工作线程不得整体中断。

排队未开始记 START_PRECLUDED，执行中记真实 EXIT_OBSERVED；周期重排、父子及迟到后继各自结清。
运行中的不可中断循环、旧 native 调用或逃出受控出口的线程明确未决，不因取消返回 true 冒充退出。
等待者得到取消或受控失败，不通过直接清空 Future 方法把它永久挂起。

同组所有任务句柄、队列引用、私有缓冲、文件／Native 句柄、票据和 reservation 沿现有资源工作释放。
整组释放不等于重复 free 未知句柄；未知副作用沿原意图查询，实际释放后结清。
私有对象被回收、进程退出或执行入口被封，均不能代替仍需证明的资源处置结果。

### 8.2 保存必须接真实句柄

以目标 Mod 全部已登记保存源为集合：其 SavedData、持有记录、保存任务和外部文件写入一起控制。
Mod 私有文件可按选定处置语义整体处理；混合存档处理全部目标组记录并保留其他 Mod 和未知字段。
不按文件名／目录名猜归属，不以整份删除世界或停掉所有保存代替整 Mod 持久终结。
完整对象数据、已注册方块／物品的存量引用需要对应迁移或处置，停方法不会自动卸载注册表。

从实际保存流取得文件身份、来源与保存代次，关联编码和保留范围。
准确非法写入应在破坏性 open/truncate 前被拒绝；不能写坏基线后再靠覆盖回去宣布拦住。
同文件中组外记录、未知字段与组外合法新保存继续保留；目标组自己的其他记录仍纳入处置。

沿用 Windows 本地 NTFS、运行时可用的 TxF 首后端：
事务内复验身份/基线 → 写完整候选并检查事务图像 → 最终提交门 → 独立重新打开读回。
能力不足明确未决，不静默退回普通覆盖并沿用同等成功语义。
TxF 的平台寿命和可用性继续按运行时条件处理；替代后端必须满足同一提交合同。
[微软 TxF 说明](https://learn.microsoft.com/en-us/windows/win32/fileio/deprecation-of-txf)。

每个保存代次独立工作身份，同一意图重试保留原 key/attempt。
重启先枚举原意图，再按已登记来源重新定位 holder、代码和文件；不用旧指针，不扫任意第三方文件。
匹配预期图像及保留事实后登记读回；基线没变也先查清旧事务不再可能提交，不能直接重放未知动作。

### 8.3 完成与调度

完成观察绑定持久操作身份；实体回收或活动缓存淘汰不删除未结工作。
未知来源、不透明效果、未加载 holder 和不支持的必要路径继续保留具体原因。

满足必要条件后沿用 **20 tick 稳定窗口、最大 10 tick 采样间隔**。
目标相关的新源、任务、回插、代码/资格或保存代次变化立即撤销当前完成，历史事实保留。
整组范围内任何成员的新活动都影响该组完成；组外任务和保存不会反复打断此链，真实捕获损失仍按影响处理。

使用依赖变化、脏标记、有界预算和公平轮转，无新证据时限频重查。
预算耗尽保留义务并恢复调度，不能永远空转或静默丢弃工作。
20 tick 不是定时器最长延迟，不能用加长窗口补偿漏掉的重建来源。

### 8.4 整组原意图与重启

复用现有 operation／generation／attempt，持久化批次选集、去重后的实际作用组、逐组代次、来源定位及所需后端版本；重启保留逐组结果和未决，不重放已经完成的其他成员。
重新启动时先读原停用意图，再解析当前实际 Mod 载体并建立最早可用入口；未加载来源等候，
文件替换／版本变化保留绑定缺口，不能把旧指针或旧模块名当作新作用组。
只关闭当前会话执行与跨重启永久停用分别显示。撤销规则不自动复原丢弃的实体、失败初始化和已提交保存。

学习 EOP、Arcane 和回响物语的模型内遮罩、程序化 shader、分层透明与连续时间参数，
直接复用可以复用的现有实现。动画按实际渲染帧插值，60 FPS 是目标环境下的表现目标，
不把 20 TPS 逻辑计时写成 20 FPS 动画，也不承诺所有硬件固定 60 FPS。

清掉重复打包资源和无调用占位实现，复用公共依赖与共享适配；强度增长应能指出新增的真实入口。

### 配置和状态入口（不是启用防护的前提）

- /ronova_pro mod stop <modid[,modid...]>：一个请求停用多个目标，合并真实载体并逐组报告结果。
- /ronova_pro mod protect <modid[,modid...]>：一次保护多个完整 Mod；Ronova 自身关键链默认受保护。
- /ronova_pro mod status <modid[,modid...]>：显示所选集合及逐 Mod／实际组的进程、双端、存量和来源结果。

示例：/ronova_pro mod stop example_a,example_b,example_c。
单个 modid 是同一批量入口的单成员用法；界面多选提交同一种请求，不建立第二套执行实现。
逗号分隔的名称逐项解析并去重，当前语法不隐含“全部已加载 Mod”或对新 Mod 的永久通配选择。

旧 clear／protect 命令保留其已有单对象语义，不能悄悄把旧脚本扩大成整 Mod 操作。
经过已接入引导的启动自动落实自保和已保存选集；界面多选与下列 mod 指令负责配置或运行期调整，不要求玩家每次启动手动激活。没有 live-enable 成功语义前不提供假恢复按钮；
解除规则不重放已发生效果，需要重启或持久接续时明确显示。

客户端／专用服分别解析本地真实 modid 来源。单边停用不显示成双端成功；
远端请求必须来自客户端已授权接受的服务器策略，并绑定当前会话，不能让任意服务器停用本机任意 Mod。
新连接、断线／换服和客户端缺少对应 Mod 时按真实状态处理，不继承上一个服务器的权限。
