# V1.4 平台依据与实现边界

日期：2026-09-20。**R3 保留 R1/R2 的平台边界，并核对 NativeMethodBind、Windows 进程创建和文件预操作接口；不是输入源码已实现能力。** 原设计最高目标保留；接口不能提供的功能必须寻找真实后端。只核对设计确实涉及的接口，不展开未采用驱动的安装器/签名工程。

## E01 · Java 17 重转换与已经运行的代码

Oracle 的 Instrumentation 文档说明，重定义/重转换不替换正在执行的旧栈帧；旧调用继续使用旧方法，新调用使用新定义。因此不能在攻击开始后才重转换一次，就声称已进入的攻击代码被停止。设计要求：尽量早装真实门；已进入调用的下一次受保护写入/提交仍受现存门约束，或者明确在途缺口。

来源：[Instrumentation，retransformClasses / redefineClasses](https://docs.oracle.com/en/java/javase/17/docs/api/java.instrument/java/lang/instrument/Instrumentation.html)。

## E02 · ClassFileTransformer 不是通用 veto

返回 null 表示不提供新字节；转换器抛异常也不等于阻止加载，其他转换器仍可运行。自己的输出不是天然的“最终获胜字节”。设计要求：要么确有可拒绝的定义/发布控制点，要么提供有效的受控变换，并对最终生效入口、顺序和已有副本进行确认；不靠故意异常宣称已拦类加载。

来源：[ClassFileTransformer](https://docs.oracle.com/en/java/javase/17/docs/api/java.instrument/java/lang/instrument/ClassFileTransformer.html)。

## E03 · JVMTI 观察不自动等于阻止

FieldModification 提供修改事件参数，其通知回调没有普通布尔拒绝返回值；仅登记 watchpoint 不能直接推出每次写入都被 veto。某些原生绑定接口有不同的修改能力，也必须按具体接口、能力和阶段分别验证。设计要求：对受支持写法在写入者或真实消费/提交边界施加门；原始内存已被改再补回属于 breach 后修复。

来源：[JVM TI 17，FieldModification / NativeMethodBind](https://docs.oracle.com/en/java/javase/17/docs/specs/jvmti.html#FieldModification)。

## E04 · Future 取消与退出

Future.cancel 表达取消尝试，是否中断正在运行线程由参数和实现条件决定；不能据一个返回值证明任意运行体立即退出。设计保留 START_PRECLUDED 与 EXIT_OBSERVED 的区别；0 延迟回调若已进入，只能对尚未发生的后续受控效果前置阻断，不能修改历史为“从未进入”。

来源：[Future.cancel](https://docs.oracle.com/en/java/javase/17/docs/api/java.base/java/util/concurrent/Future.html#cancel(boolean))。

## E05 · Forge Event 的能力范围

只有相应事件及其实际发布/取消语义才能形成事件级拦截。没有经过该事件的调用路径不被它覆盖。Mixin 位于方法 HEAD 也只是相对于该方法；调用者参数求值或更早业务效果并不会倒流撤销。

来源：[Forge 1.20.1 Events](https://docs.minecraftforge.net/en/1.20.1/concepts/events/)。后一句为按程序调用顺序作出的设计推论，不是 Forge 声称所有 HEAD 都无效。

## E06 · Host 预防要采用实际可控接口

Windows 映像加载通知回调没有拒绝返回值，不能把收到通知后卸载/终止称作“加载前拒绝”。对象句柄预操作接口可按文档约束削减可修改的访问权，但不能任意增加权限；也不直接控制同一 JVM 内的一次 Java 字段写入。

来源：[PLOAD_IMAGE_NOTIFY_ROUTINE](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntddk/nc-ntddk-pload_image_notify_routine)、[OB_PRE_CREATE_HANDLE_INFORMATION](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/wdm/ns-wdm-_ob_pre_create_handle_information)。

Host/驱动/模块准入/访问控制的能力目标继续保留，限受用户授权的测试/部署范围；必须证明实际访问或执行被阻断，平台授权与代码签名条件保持真实。不得把绕过系统授权、安全组件失效或不可卸载驻留当作强度验收，也不在本次文档修订中执行这些系统操作。

## E07 · TxF 当前选择与寿命

当前包的 Native 保存后端是 TxF 事务，不是通用内核自保。微软建议新软件评估替代方案，TxF 的可用性需按平台实测。设计保留当前原意图/提交前门/独立查询合同；不因接口寿命问题直接降为普通覆盖，也不在本次 MD 修订擅自换后端。替代后端只有满足同一合同并独立验证，才可接入。

来源：[Alternatives to using Transactional NTFS](https://learn.microsoft.com/en-us/windows/win32/fileio/deprecation-of-txf)。

## E08 · 本次设计推论：层次高低不是成功证据

“更底层”在本设计中指：绕过不可信公开 getter/可覆写方法/单一事件，接近准确状态变更、注册、执行与提交点。“更前置”指：在受保护效果首次不可逆或可被业务观察前阻断。二者须同时按具体路径判断。

发生在底层但只能事后收到的通知，不比位于真实写入前的普通 Java guard 更前置。同权限代码若能改写策略及门本身，纯进程内软件不能仅凭自称 Root 就推导出绝对不可绕过；必须覆盖实际干预途径并保留未证明范围。该事实不删除最高能力目标，只禁止虚构完成。

外部资料只约束实现真实性，不替代 [源码对照](源码对照与前置阻断落点-V1.4.md) 或 [本版验收合同](前置阻断验收合同-V1.4.md)。

### R2 的实施解释（推论，不是新的平台 API）

“门先装好再绑定目标”“限定对象的代码/分派控制提前到 A”是本项目选择的设计顺序。它们不改变 E01–E03：旧活栈不会自动改跑新字节码，transform 返回 null/抛异常不是通用类加载拒绝，FieldModification 通知不是写前否决。作用点必须真实可控，暂时不可控的路径仍不能冒充已覆盖。更多前置要求不构成任意 Native 写入免疫的证明。

## E09 · NativeMethodBind 有绑定重定向能力，也有范围

JVMTI 的 NativeMethodBind 在 Java native 方法实际绑定时提供原地址和可写的新地址位置；具备相应能力的 agent 可以改变该次绑定。它是具体 Java native 方法的绑定能力，不是任意本机函数/内存写入的通用 veto。声明 native 支持必须处理正确 ABI、当前方法/加载器和重绑；既有已经运行的调用仍按实际效果处理。

来源：[JVM TI 17，NativeMethodBind](https://docs.oracle.com/en/java/javase/17/docs/specs/jvmti.html#NativeMethodBind)。R3 将必要绑定后端提前属于项目选择，不说明 Secret 的原生实现或 Ronova 已经过实测。

## E10 · Windows 访问、创建与文件控制须分别落实

- 进程创建通知使用的 `PS_CREATE_NOTIFY_INFO.CreationStatus` 可由驱动改为错误，从而拒绝创建。父 PID 不等于唯一创建者身份，必须使用实际上下文；R3 限本方授权子进程关系，不扩大到任意系统进程。[微软接口说明](https://learn.microsoft.com/en-us/windows-hardware/drivers/ddi/ntddk/ns-ntddk-_ps_create_notify_info)。
- Minifilter 可在适用 I/O 的预操作回调中完成请求并设置最终状态；不是所有操作都能以错误拒绝，文档明确 cleanup/close 完成状态必须成功。因此它可作为准确文件 I/O 的后端候选，不能拿来宣称能任意拒绝所有资源关闭。[微软预操作完成说明](https://learn.microsoft.com/en-us/windows-hardware/drivers/ifs/completing-an-i-o-operation-in-a-preoperation-callback-routine)。
- 对象句柄访问权与映像通知仍按 E06。需要控制具体 DLL/模块时必须找到真实可控的加载/绑定或部署策略，不能由创建控制和映像通知自动推出所有模块均可拒绝。

上述是接口能力核对。安装/签名、目标身份、已存在句柄、映射 I/O、并发和退出条件仍需实现；本轮没有加载驱动、修改 OS 权限或执行样本。Host 的强度按它实际能拒绝的效果计算，不能按组件名字计算。
