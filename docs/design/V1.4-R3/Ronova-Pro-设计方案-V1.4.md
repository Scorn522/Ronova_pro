## 1. 本版纠正的问题

用户报告当前候选无法清除三个目标，已经执行保护仍被移除。这些是实际失败，不能用自有夹具通过数量抵消。

本轮日志还证实：一个已存在于内存、尚未写盘的恢复源没有进入必要工作；系统曾短暂登记恢复链完成，随后出现新 UUID 身体才撤销。自有复现中，旧包也在延迟重生前提前报完成。

因此 V1.4 调整基础要求和实施顺序：

| V1.3 实施暴露的问题 | V1.4 的决定 |
| --- | --- |
| 主要依赖普通生命周期入口，底层数据被直接改写后能力不足 | 原字段、真实容器、实际调用入口、客户端镜像都进入通用基础 |
| 容器身份一变就长期停止处置或修复 | 撤销旧绑定后主动定位当前载体；满足当前对象及语义条件则继续，不永久等待旧容器回来 |
| 防御以 tick 末补血、补索引为主 | 常态必须前置拒绝/无效化；修复只在独立事故路径，不能补交前置防护 PASS |
| 来源发现依赖首次文件保存，包装记录没有进入义务 | 从真实内存持有关系开始发现；首次写盘不是恢复源出现的起点 |
| 无 NBT 主要用 Object.clone 代表 | 构造器新建、工厂返回、字段赋值、静态持有、任务和通信重建分别覆盖 |
| 大量协议路径通过后被概括为基础强度达标 | 基础攻击和防御有独立、必须全部通过的出口；任何一边不成立都不能交付强度达标版本 |
| 将未知显示出来被误认为已经解决 | 明确未决是正确诊断，但正例仍不通过，必须继续补实际执行能力 |

最高能力目标不降低。弱伤害招式、重复包装层不增加；原有任务、Native、Host、世界和视觉目标也不删除。

### 1.1 本次不是再加一组“更强开关”

原有全部能力上限、16 Primitive、10 Executor、5 Outcome 和 39 组场景不删，也不再增加 Pro 档位。改变的是每个能力的**截断时机与真实作用点**：

```text
旧常见路径：对方写入/注册/运行/发布 → tick 看到 → 补回/清走
本版主路径：真实操作到达最早可判定点 → 准确策略当场拒绝
           或未产生外部效果的运算 → 在首次提交/发布前无效化
突破后的兜底：记录 breach → 局部封出口 → 修复/清理 → 重验
```

“执行优先”只指 **Ronova 的已授权阻断不等待后台审计**，绝不指先让对方执行。目标身份、跨对象 lineage、不可逆操作和外部资源处置的正确性仍保留。

当前源码重点缺口：保护等 ACK 才激活；异步 guard 不读取有效策略；首次新身体需先被清除才受准入拒绝；后台反复删补代替写入门；客户端仅查询缺席。现有任务前置 fence 和 Native 提交前门是可复用资产，不整体重造。

## 2. 通用基础必须达到什么程度

这里的“基础”是 Pro 首个可用攻击/防御版本必须具备的能力，不是普通伤害或一次 `remove()`。

| 控制面 | 攻击必须做到 | 防御必须做到 |
| --- | --- | --- |
| 当前身体与生命状态 | 绕过目标的空实现、拒绝式回调及不可信 getter，处置准确身体；生命值、生命来源和死亡语义各有原语 | 拦截受支持的伤害、死亡及非法生命写入；处理 NaN、无穷值、最大生命破坏及死亡标志漂移 |
| 世界记录 | 先封准确回填/发布，再清 ID、UUID、Section、Tick、Tracking 中目标记录与别名 | 非法条目写入、删除、整容器替换在提交前拒绝；合法换代无保护空窗。被绕过后的重定位只记事故恢复 |
| 对象状态与关系 | 在目标 callback/更新/登记结果发布前使之失效，再处理适用乘客/载具/多部件关系 | 非法 callback、更新资格、包围盒和关系变更在写前拒绝；合法移动/新关系必须继续，旧快照不回写 |
| 回插和恢复源 | 原对象第一次非法回插即被拒；准确源读取/任务/输出入口受控，随后处置静态、SavedData、包装等源 | 合法身体/任务/状态被针对的非法操作先被挡住；撤销保护和合法释放有明确顺序 |
| 新身体重建 | 无 NBT、新 UUID、工厂/构造重建能沿实际 producer 关系接续并阻止 | 合法替身、传送、重生和新代身体正确接续；旧指针不能永久冒充当前身体 |
| 运行入口 | 已知相关防御实现/回填调用在实际进入或结果提交前受控，不受单一可覆写 API 否决 | 关键 gate 被替换的间隙必须由独立有效截点封住相关效果；事后修回不能冒充持续无突破 |
| 客户端和对外存在 | 在陈旧包处理、镜像登记、额外绘制提交前拒绝目标旧结果；既存状态另外清理 | 客户端非法移除/旧代消息不能先改变合法镜像；若已经变更，恢复只能记为修复，不记前置防护 |

原语作用于具体对象和关系。单体、射线、范围共用实现，只改变目标选择；范围操作也不能退化为按类名批量删对象。

**基础出口必须同时包含进攻和防御的完整组合场景。** 只有诊断、拦住普通 API、能清理普通动物或能修复一张未替换的表，都不满足本版基础。

<a id="architecture"></a>
## 3. 小体积结构与共用模型

继续使用 `Primitive → Executor → Outcome`，保留 16 组原语、10 个执行职责和 5 类 Outcome。它们是语义分类，不规定每项新建一个类、服务或线程。

| 共用部分 | 唯一职责 |
| --- | --- |
| 当前对象及载体解析 | 统一取得 realm、准确对象、原字段身份、加载器、当前容器和代码版本 |
| 执行原语 | 直接读、比较、移除、恢复、拒绝和必要结果查询 |
| 当前策略 | 管理攻击/防护意图及当前代次，支持即时撤销；不复制三套权威 |
| 工作与义务 | 只为确需跟踪的异步、跨对象、不可逆和持久效果维护统一工作 |
| 调度与观察 | 共用有界队列、脏标记、依赖唤醒、优先级和稳定观察 |
| 诊断与界面 | 投影真实状态，不能授予许可或自证结果 |

Entity、World、Task、Reconstruction、Storage、Presence、Runtime、Code、Integrity、Host 继续作为执行职责。Network/Input 跨 Presence、Runtime、Reconstruction 共用，不另建平行框架。

保留 `SubjectKey`、`QualificationGeneration`、`Incarnation/Binding`、`OperationId/WorkKey`、`RuntimeSession`。准确对象和当前代次进入短执行路径；每个按钮、字段、容器条目不再各造一整套 Permit/Receipt/Observer。

同一个目标的“清理登记”和“恢复登记”共用载体解析和准确写入原语，参数表达方向。攻击策略与保护策略冲突时，由同一权威按当前明确请求和代次裁决，不能同时反复删补。

生产载荷只保留必要执行、观察与查询能力。测试驱动、审计报告、大图、符号和未支持平台文件独立打包；同时报告 Core 和完整安装体积，不能靠把内容移到其他包来伪造总量下降。

<a id="preemption"></a>
### 3.1 最早有效截点，不是五层顺序审批

每条必需路径选择能确认目标关系、又能早于有害效果的真实截点。多截点并联/兜底，**不要求一次操作顺序穿过五套门**。

| 截点标签 | 位于哪里 | 攻击用法 | 防御/拦截用法 |
| --- | --- | --- | --- |
| DEFINE / BIND | 代码、委托、加载与资源绑定投入使用前 | 使已确认的目标防御/重建实现不能成为实际生效实现 | 关键 guard/分派/资源的新副本未受控则不得作为有效受保护路径发布 |
| SUBMIT / ENTER | 实际 source 读取、任务提交、回调/工厂进入前 | 阻止准确恢复 producer/本次回调运行；不得先运行再据 EXIT 宣称提前击毙 | 阻止明确非法的攻击调用抵达关键执行段；共享线程/方法不全禁 |
| WRITE / REGISTER | 字段、集合、slot、manager 或新身体注册提交前 | 禁止准确目标回填和结果进入世界/索引 | 拒绝伤害值、移除状态、非法索引删除和载体替换 |
| COMMIT / PUBLISH | 真正外部写入、可观察状态/包/图形提交之前 | 已在途 producer 计算出的新身体/结果不取得外部效力 | 对方可完成纯计算，但非法结果不能改变身体、世界、磁盘或远端显示 |
| REPAIR | 有害效果已经发生之后 | 清除漏网身体/缓存并处置源 | 记录突破、补救、重验；**不算上述任何前置成功** |

实际字段/载体/写入者、JVM 原生绑定和 OS 访问边界分别解决不同绕行路径。能在更早的真实效果点完成控制，就采用该后端；只能收到通知的 Native hook 不冒充可拒绝接口。[平台依据](平台依据与实现边界-V1.4.md) 区分每种接口的真实权限。

### 3.2 共用短门需要的数据

在已有 Subject/Binding/策略记录中发布一个最小当前快照，语义至少绑定：realm/session、准确 subject/incarnation、qualification generation、策略 revision、对象/载体身份、动作方向、覆盖的入口版本。实现可共享对象，不要求逐字段新建类。

所有读者都看到完整快照，不能分别读到新代次、旧保护位和旧容器。保护激活、策略撤销、合法换身与写入授权有明确定序点。guard 可以在实际调用线程进行只读判断；世界结构写入仍遵守拥有者线程/容器并发合同。

准许合法动作必须绑定真实 operation 与准确 effect，不能只认“类名是 Ronova”“当前线程可信”或一个全局 bypass=true。Ronova 清除中的回调重入、异常退出和异步提交都不能泄漏该例外。

### 3.2.1 最小前置决策，不先给攻击者做完整溯源

防护的常见短门只需回答：**这次真实变更是否会影响当前已绑定、保护已激活的对象/槽位/结果，是否违反当前动作合同？** 能确定就当场拒绝；不必先查清“哪个 Mod、哪个任务、哪条完整攻击来源”才保护自己的生命或索引。

攻击同理：准确旧身体、已确认的回填边和目标结果出口可以立即按当前授权控制；完整 producer 图用于继续向上游处置与判定整链完成，不成为所有准确原语的共同启动门。跨对象归属未知的部分仍不能靠类型、名字、位置猜测后误杀。

共同短路径是 `准确实际对象/变更 → 已发布当前策略 → 合同内允许或拒绝`。实际需要定序的写入与撤销共用短门；不做磁盘读写、全图扫描、类名归因或每次新建 permit。基类方法可覆写时，决策贴近已确认的真正 writer/载体，不依赖目标自己回答“能不能清”。

### 3.3 攻击、防护、拦截的统一控制表

| 实际控制面 | 攻击前置目标 | 防护前置目标 | 突破后的独立兜底 |
| --- | --- | --- | --- |
| 生命/状态/附加数据 | 阻断已确认恢复写入/防御结果，执行准确生命与身体原语 | 拒绝第一次非法状态变更及死亡/掉落/能力回调 | 从当前合法事实修复，报告实际损失 |
| 容器/索引/关系 | 拒绝旧对象和旧代结果写回、补索引、改 callback | 拒绝删记录、别名改指向、整容器/manager 非法发布 | 当前载体重绑定，保留合法占位 |
| Task/Callback/Event | 对准确任务/本次委托从提交或进入前阻止，迟到后继同理 | 明确非法任务不能写受保护效果；事件总线不是唯一入口 | 在途调用结果封住，EXIT/资源另外结算 |
| Factory/Source/Admission | 准确源读取/工厂副作用/注册前截断；处置源而不只拦蛋 | 合法重生换身正确交接；无关同类型不被牵连 | 漏网实体独立清除，不伪造无 NBT 来源 |
| Network/Input | 旧请求/镜像/回放不能进入相关业务/结果发布 | 非法移除包/重放输入在 handler 副作用前拒绝 | 重同步为修复，required 客户端缺失仍 UNKNOWN |
| Presence/纯渲染 | 渲染登记、draw 提交、旧缓存重发布前阻断 | 自身绘制/资源不被非法替换或隐藏 | 清理已提交缓存并恢复，发生过错误帧不能改成从未发生 |
| Save/World/Resource | 非法持久重建/世界回填在真实写入前被阻止 | 基线文件/区块/资源发布不能先损坏再补 | 原意图查询、回滚/补偿、独立读回 |
| Code/Runtime/Host | 精确相关实现/调用或授权 Host 控制范围内的结果失能 | 实际定义/模块/访问边界前置控制，保护门自身连续有效 | 恢复/重启不是首次入侵前已阻止 |

同一控制面三方向共享原语，但 CLEAR / REJECT / RESTORE 结果不能串台。Network/Input 不由 Presence 的缺席探针代替，Host 不代替 MC 的准确对象原语。

<a id="r2-forward"></a>
### 3.4 R2：更早取得真实控制权，不只是增加前置条件

**R1 已有即时 guard、真实 writer、先封回填、0ms 提交、门连续性及效果零泄漏要求，R2 不把这些重新宣传成新发明。** 本次改变：把基础实际代码/分派与针对已确认源的主动处置从后续完整阶段抽到 A，并将“可拦截”落实成当前攻防必需的执行路径。§12 与矩阵的显式阶段范围优先于旧的“完整代码都在 C”概括。

#### 3.4.1 将安装和定策分开：门先在，目标后绑定

在受支持的 Forge/JDK 启动、类定义、载体/委托登记阶段，为本轮基础声明的真实 writer、登记、调用及呈现出口准备共享执行门。尚无目标策略时不限制正常业务；实际 target 绑定后，发布同一个最小当前策略即可开始保护或压制，不能每次受攻击才发起扫描、编译、重转换或等待下一 tick 安装。

已加载类需要补转换的，在基础功能发布可用前完成；后续新类、重定义和合法新载体要完成同一策略交接。早装的是门，不是提前猜敌人，更不是阻止全部 Mod 加载。若目标使用尚未覆盖的必要路径，先保持已有准确保护并明确该路径缺口；不能短暂放行后追认从未受损，也不能把启动能力缺失拖成每次操作的全局等待。

启动时直接准备本批必需 hook；涉及外部持久变更或未知副作用的步骤按 §4 分流，战斗热路径不逐次授权代码安装。玩家免手填参数按 §11.1 的真实启动后端实现，不凭 Mod 已加载宣称 premain 已发生。

#### 3.4.2 控制真实生效实现：限定对象的代码剥离和反全返回进 A

A 不是“装几个 HEAD 再等 C”。其最低范围必须包含：当前基础攻防的实际覆盖方法、调用点、状态写入、回填 callback 与分派；已确认目标相关防御/恢复实现的条件性失能；本方必要入口被改成空返回、固定返回或错派发后的继续执行及恢复。

PR12/PR13/PR15 共用一条真实能力路径。方法按准确 receiver、实际输入/输出关系、定义加载器、当前 operation/effect 与代次控制，不能因方法被一个目标使用就删除共享类、吞掉所有回调或全局返回。RETURN/THROW/ABORT/SUPPRESS/REWRITE 只在匹配的调用合同内采用；拒绝要结清必要异常、finally、Future 和资源语义，不能让等待者永久悬挂。

该范围必须把 **实际定义/字节 → 实际 dispatch → completion → final state** 接起来。不是四个新验证器：使用现有代码后端、操作记录和真实执行位置。只校验字节/指纹不交付该能力；只把返回值改成 false 也不清除已有副作用。全面动态代码、所有 JVM/Native 路径仍归 C，基础真实执行不得等待 C 才补。

#### 3.4.3 对目标的写入资格双向控制，不依赖它报告身份

当前准确对象的保护/终结关联由 Ronova 自有的对象身份索引和合法 Binding 交接提供；原 UUID/ID/level 是载体观测，不是每次查找策略的唯一入口。已经绑定对象的这些字段被破坏时，不得因此查不到策略并放行；合法换维度/换身必须准确交接，不能冻结旧 level 或旧 UUID。

同一个实际 writer 按动作方向工作：保护时拒绝非法减血、死亡、最大生命/同步数据破坏、移除、禁更新、非法载体或装备变化；终结时拒绝已授权准确目标的非法回填、恢复生命、重新登记和陈旧结果。真实最大生命、附加存活来源、DataItem 与业务消费分别适配，不能只维护显示用的 health 值，不能无条件信任被压低的当前 maxHealth。合法变化继续使用当前合同，不把保护写成全字段冻结。

#### 3.4.4 来源级攻击进第一批：能够剪断，不只能够看见

A 同一生产批次必须具备：当前准确旧身体/回填边拒绝；已确认的静态或 SavedData 包装记录份额实际处置；本次 producer/工厂/提交/回调在可准确归属时先于副作用拒绝；仅能输出归属的路径在第一次危险发布前限制。HashMap 包装记录、无 load 的实际构造/工厂新 UUID 以及已知回调重新登记，不能只交一个扫描器或 Object.clone 演示。

不要求等所有来源、磁盘和任务图闭合才清当前身体。先控制可确认的输出，直接清体并剪断已确认的可幂等内存源边；真实持久变更和未知副作用按 §4 分流；B 再收齐整个支持范围的发现、后继、资源和持久重启。共享 holder/工厂只处理目标份额，真实读写并发合同不得凭只读发现授予。对关系未知的源，保持观察/未决而不批量误杀；它不撤销已知对象的有效门。

反复使用已处置源时，重复尝试在已存在的同步门被拒，不反复新建同一工作、重扫描全图或刷盘。已结束操作的迟到任务/新输入仍产生准确的新义务。临时压制可早生效，真正源终结仍要求源被处理，不能以永久保留 guard 冒充 O02。

#### 3.4.5 身体动作不被对方回调和无关缺口挟持

沿一个准确 Operation 执行：当前会话封住已确认写回/发布；raw 状态、各适用索引、关系与 tracking 份额直接按真实依赖推进，不统一等待日志 ACK。未知生命周期/移除通知单独查询，不能让某一回调异常或未知效果阻止与它无关、已经授权的幂等数据层步骤。

没有足够观察来确定某一步是否执行时，不重放该步；不透明回调也不能被任意跳过后宣布死亡/掉落/资源已完成。O01 仍等其全部适用义务。独立补血、火焰及当前许可的记录修复不因另一张表暂不可定位而全部停掉；非法整 manager/callback 发布与合法更换都要有真实控制和交接。

同对象同资格的幂等回插处置复用已授权范围，不因换一张同语义表而重复排一个全新 CLEAR/ACK。新身体、真实新副作用和变化的持久范围仍按 §4.2 创建必要工作。旧工作被接替时实际交接已发生效果及引用，不能只改 FENCED 字符串；callback 快照等自身持有引用也必须在其生命周期结束时释放。

#### 3.4.6 基础呈现、UI 与玩家交接不拖到最后

A 同批完成当前准确对象的真实 tracking/客户端镜像、已绑定 HUD/BossBar/绘制登记与必要 UI/输入路径。前置拒绝陈旧移除/假死亡界面、已确认有害 overlay 或 handler 对 ESC/背包/输入的非法阻断；合法死亡、断连、关闭 Screen、打开菜单、传送和重生继续工作。合法输入沿原协议执行，不伪造键鼠或发送重复命令。

明确绑定的纯渲染目标同样使用其真实 owner、回调和 draw 份额，不依赖虚构 Entity；共享 batch 仅处理本目标份额。没有 owner/数据流依据时不能凭长相删除 renderer。激活前已提交帧只能另行清理；仅服务端存在策略不能保证未安装配套客户端的远端 UI。完整渲染资源图、跨域高级呈现和视觉迁移仍在 C，但“客户端只有 absent 探针”不能交付基础呈现。

#### 3.4.7 更早不是凭空增加绝对权限

独立截点至少要在实际作用位置或可独立维持的实现上有效；同一个可被替换方法里的两个 if，不等于独立防线。writer 在途时，未经过新代码的旧 frame 只能由其仍会经过的有效写入/发布门约束；已经绕过全部真实控制点的写入必须记为突破，不能把消费者读回合法值冒充原值从未受损。

未采用的驱动/签名/Host 服务不空建；基础确实需要的 Native 控制按 R3 §3.5 和 §12 提前。任意停线程、冻结整个世界或关闭共享池不能作为准确控制的替代。进程内 Java 快照或一份 DLL 均不能自行证明任意同权限 Native 内存破坏已被覆盖。

<a id="r3-control"></a>
### 3.5 R3：把控制落实到执行、写入、派生、发布与释放

R2 已经要求先安装门、再绑定策略。R3 的增量是：**同一策略必须实际决定目标份额还能做哪些动作，并在拥有该效果的入口执行决定。** 不是把更多检查插到原 HEAD；不是给每次字段访问再发一张证书。以下动作属性进入既有 Binding/operation/资源记录，复用现有 generation、commitGate 和后端。

#### 3.5.1 一份当前策略，多个实际执行位置

| 受控动作 | 更早、更低的实际落点 | 必须改变的行为 |
| --- | --- | --- |
| 定义与绑定 | 首次相关定义/重定义、方法实际分派、委托安装、受支持的 Java native 方法绑定 | 新实现未接上当前门时不发布为可用路径；针对准确 invocation 选择受控执行或拒绝，不全局清空共享方法 |
| 执行与读取源 | 实际 listener/delegate 消费、准确恢复记录读取、工厂调用者的首次副作用之前 | 已封锁源份额不再被用于恢复；已入栈调用只保留其仍被允许的效果，不能借“运行中”继续发布坏结果 |
| 写入与替换 | 原字段、DataItem、真实 backing slot、manager/callback 持有字段、支持的 CAS/反射/句柄写入 | 拒绝值写坏、删槽位、换指向；不会在查询端返回假正常值来掩盖真实破坏 |
| 派生与入队 | 准确任务的入队/调度交接、本次 continuation 绑定、producer 输出登记 | 旧代不得凭换包装、换 worker、重新排队获得新执行范围；共享委托上的无关调用继续运行 |
| 发布 | tracking/包排队及消费、世界/存储提交、准确 draw/batch 提交 | 禁止非法结果第一次取得外部效力；仅在最后改返回值不能抵消此前包、帧、写盘等效果 |
| 释放与拆除 | 本方必需 callback、队列持有边、Native/文件/图形资源的准确关闭或解绑 | 非法拆门、提前 close/free 被真实拒绝；合法停服、换代与卸载按原操作释放，不能永久泄漏 |

“撤掉写入/执行权”指这些已安装落点实际不再执行对应动作。它不是给普通 Java 对象添加一个 JVM 会自动强制执行的权限位。没有覆盖的任意原生直写、已有裸地址或未观测别名继续是具体缺口；已有准确保护保持有效，受影响的完整结果不得完成。

策略在请求时立即生效于已准备的当前范围；普通内存动作和启动 hook 直接执行；仅 §4 列明的持久或未知副作用沿原意图处理，不能把每次读策略变成新 ACK。持久审计只记录真实变化，重复命中不生成一串等价工作。

#### 3.5.2 从公开方法下沉到实际槽位和变更操作

绑定单位是实际 owner、字段或 backing identity、准确目标份额及当前代次。Map 视图、迭代器、别名、fastutil、数组写入和整 manager 发布共用同一个归属，不靠集合类名或可被破坏的 raw level 判定。已取得的旧别名必须在其真实写入点受约束；仅换掉上层 Map 不能宣称旧引用失效。

对批量 clear/removeIf/replaceAll、计算回调及 CAS，需要保留 API 的实际返回/异常和并发合同。支持可分离的混合操作时只修改被允许份额；不可分离时在第一项副作用前按明确合同拒绝整次请求，并报告连带未执行范围。不能先执行任意 predicate/remapping 回调再“预判”，也不能把 CAS 拒绝伪装成成功。由 bulk 请求产生的合法邻居操作须可单独正常推进。

本方清体走准确 raw 状态和真实数据结构的执行路径，不让目标覆写 remove/hurt、吞 Event 或固定 getter 决定是否执行。原容器确有不可信实现时，在其拥有者的同步协议内发布保留其他份额的新载体，并同时处理已有视图、读者和正在迭代的版本；不能恢复整张旧表抹掉合法并发写入。身体、Lookup、Section、Tick、Tracking、关系和纯呈现分别真实处置。

#### 3.5.3 对输入、派生和资源的控制早于放大

准确已知恢复源在记录取用和工厂第一次副作用之前截断；来源暂只能在输出确定时，严格保留“工厂已运行”的事实并封住首次发布。读取/解码过程若已有文件、构造、任务等副作用，其边界单独受控，不以空结果假装这些动作从未发生。未知 lineage 不按类型、显示名或位置扩大。

任务的入队、实际出队/委托进入、再次入队、后继绑定分别使用当前准确 invocation；父任务退出、Future.cancel 成功都不撤销后继义务。拒绝入队要履行 Executor 的拒绝/异常合同；接受后又阻止开始，要结清对应 Future、等待者和准确引用。合法共享 worker 不暂停、不终止，旁路提交仍由同一实际效果门处理。

将准确已知 producer 的输出配额、候选缓冲、任务 reservation 和私有 Native 分配检查放在实际分配/接受前，防止先放大再靠清理赶上。预算只限制拥有明确归属的份额；共享池/全 JVM 内存不可按目标预算一刀切。预算不足时已有 guard 继续工作，未结义务公平恢复，不能把 OOM、卡死或永不完成当作控制成功。

本方关键资源也受双向控制：禁止未授权拆除门/句柄，允许明确的合法交接和实际释放。强引用延长生命周期有明确所有者与释放点；Native 返回成功、弱引用消失或停服标志不清偿资源。声明覆盖的伪造 close/free 在调用实际析构之前被拒绝，已经释放的资源不得仅靠旧 ID 重新当成有效。

#### 3.5.4 接管真实分派，保持合法业务语义

早期准备的方法/调用者变换按定义加载器和代码版本生效；对象选择仍在实际 receiver/参数/结果关系上判断。注册新 handler、替换委托、重定义、生成新类和 native 重新绑定都要在首次使用前完成当前策略交接。不能把资源中的原始 class 当成天然的最终可信实现，不能因变换注册成功就声称后续没有覆盖。

必要的本方执行入口与不可信普通 EventBus 分派解耦，但只执行属于当前操作的本方原语，保留合法事件顺序及生命周期效果。针对已确认目标调用可以条件性改写/拒绝；不整批跳过其他 Mod 的 tick、网络或世界事件。旧活栈继续运行时，尚未发生的效果由实际下游门约束；不从别的线程强拆其栈、锁或 finally。

必需门升级采用“准备新实现 → 接上同一当前策略 → 发布可用 → 排空旧使用者 → 释放旧实现”。失败时保留仍有效旧门；旧门已失守就记录缺口。Java 与 Native 不各自维护一份可能冲突的终结/保护真值；它们读取同一逻辑 revision，各自提交点与撤销明确排序。运行热路径不跨进程申请每个字段的许可。

#### 3.5.5 包、帧和文件：控制第一次实际提交

网络不能只在接收 handler 修：准确发送者/镜像关系先于相关编码副作用和队列发布绑定，消费时复核 session/generation。已经进入异步队列的旧请求在其最后可拒绝处失效，必要协议完成/引用释放仍发生；共享连接继续传合法包。已发送的错误包只能补救，不能追认“未发送”。

呈现按真实 context、资源代次、owner、batch 份额控制登记、更新、解绑和 draw 提交。必要资源在销毁前得到同一保护，句柄数值重用不能取得旧权限。混合 batch 必须有受支持的分段/重建语义，否则报告不能准确隔离；清空整帧或 SwapBuffers 前覆盖一张正常图，不证明目标从未绘制。切窗口、资源重载、合法 Screen/输入继续可用。

存储同时覆盖实际句柄的破坏性 open/truncate、写入、重命名/替换、删除及声明支持的映射写回，不能只守自有 TxF commit。路径用于定位，权限绑定实际文件/句柄/来源/保存代次；先截断再取文件身份不满足防护。共享文件内无关条目和未知字段保持原义，候选完成后才做最终短门；映射/别名或 Native I/O 尚未覆盖时不宣称完整文件防护。B 完成这一范围及原意图重启，平台条件仍见 E07。

#### 3.5.6 Native 和 Host 提供真实权限，不只是能力标签

A 可以带**本批实际用到的最小 Native 执行后端**：例如支持组合内的早期桥、准确 Java native 绑定代理和本方桥/资源的实际调用控制。接口、ABI、真实方法身份、原委托、重绑和退出都必须可落实；仅增加 GetCapabilities 或一个 DLL 文件不交付控制。Java native 绑定代理不是所有机器码写入的通用防线，也不授予管理员权限，见 [E09](平台依据与实现边界-V1.4.md#e09)。

Host 的权限目标继续保留：自动提权 / Privileged Execution、驱动、模块准入、进程/子进程和线程、读写执行权限、自保及受控恢复。实现按真实 OS 授权/签名条件取得能力，报告请求结果和实际高权限状态；这与仅显示提示不同。更强后端必须在用户授权的游戏进程及明确资源边界内产生实际拒绝效果，见 [E10](平台依据与实现边界-V1.4.md#e10)。

具体落点包括：受支持进程/线程句柄的访问权限制；准确子进程创建前拒绝；适用文件 I/O 的预操作拒绝；模块在真实可控加载/绑定路径的准入。不同接口不互相冒充：映像通知不是加载 veto，ACL 改动不自动收回已有句柄，外部句柄限制不能阻止进程内任意 native store。尚未实现的完整 Host 面仍在 C；若某项 A 的必需声明实际依赖它，必须把该项真实后端连同失败/恢复语义前移，不能只把缺口留到 C。

核心执行门、必要 Native 依赖、完整 Host 生命周期是按作用拆分的实现工作，不是“兼容/强化/极限”强度档。依赖不可用就明确受影响声明未成立；可用后自动接入当前策略。正常退出、卸载和恢复必须能完成，不以绕过系统授权、损坏安全组件或不可卸载常驻换取所谓高权限。

#### 3.5.7 本轮取舍与验收复用

[Secret 静态参考](Secret-4.1-静态参考与R3取舍.md) 提供早期自加载、统一条件 hook、实际拓扑操作、独立本方分派、帧边界补绘的参考。R3 采用前四者的通用机制；补绘仅作为呈现连续性/事故修复参考。全类型封杀、查询伪装、全事件压制、盲重放其他变换链、加密外壳和无界 spin 不作为 Ronova 的基础。

复用 PR01–PR16、10 Executor、O01–O05 和既有 C01–C39/59 个机制子 ID。矩阵及验收合同同步加入上述真实路径与合法对照，**编号不增加不代表验收工作量没有增加**。不新增通用权限框架、全局 verifier、每动作 ACK 或一门一包。先成批写齐攻防执行链及必要后端，再集中验证真实效果与旧失败。

<a id="execution"></a>
## 4. 直接执行，按实际副作用留下最小约束

**R3 按用户最新要求收掉统一前置证明：普通攻防先把准确动作做出来，完成判断和持久查证在后面。** 保留 SOFT/HARD 是为了区分少数真实副作用，不把它们实现成两套调度/许可框架。本节覆盖 R1/R2 中“身体移除、所有取消、所有代码安装一律先 ACK”的宽泛规定；历史文件只作追踪。

### 4.1 普通内存攻防直接走短路径

```text
实际对象 + 当前明确策略
→ 直接拦截 / 写原字段 / 清准确索引 / 剪已确认内存回填边
→ 记录结果；后台继续追源和结算
```

请求本身确定攻击或保护方向。已经准确绑定的对象不再等待完整来源图、能力证书、日志 ACK、下一 tick 或单独 ActionPermit。无未知回调的幂等内存清除、原值保护、准确登记剔除、已确认内存源边失效、准确任务启动前拒绝都可直接执行；正常的本地呈现更新与协议内镜像同步沿已有会话处理，不为每帧、每包另开持久意图。

共享数据只改目标份额；当前对象/代次和并发写入仍需必要的准确检查。这是防误改的实际代码，不是一次动作前跑一遍验收。身体清除不等掉落/未知通知查清，后者独立保留未决；身体、死亡、掉落和整链的完成结论分别报告。

### 4.2 只给真正需要接续的副作用保留原意图

写盘/事务提交、跨重启策略与权威 lineage、Host 权限/模块/进程/文件处置，以及不能安全重复的未知回调和资源释放，保留必要的 Intent/ACK、最终准确复核及事后查询。已发生但结果未知时沿原操作查询，不能换 key 再执行。

按具体步骤分流，不按“Entity”“Task”“Code”整类硬套。普通启动 hook 安装、当前调用内的条件拒绝或可重建会话状态，不因涉及字节码就每次先刷盘；外部持久代码/文件变更和未知副作用另走需要的步骤。自有可确定关闭状态的幂等资源按实际所有权直接释放；未知 native close/free 的执行结果必须查清，不能再次试到成功。

复用现有持久工作，不另建通用审批器。一个确需持久化的组合操作用一份准确范围；无关内存攻防继续推进。阶段出口仍要求相应持久义务完成，**无需先完成整个出口才允许开始攻击**。

### 4.3 同一个操作里的先后关系

| 情形 | 直接实施 |
| --- | --- |
| 请求攻击准确目标 | 先封已确认回填/发布，再清原身体和适用索引，处理已确认内存源；剩余源继续追 |
| 保存/未知回调尚在等 ACK | 只等待对应副作用；已经能做的内存清除、保护和阻断继续 |
| 保护请求 | 在已安装真实入口立即发布当前策略；返回已激活后不能留出下一 tick 的空窗 |
| 合法换身、换载体或撤销 | 用已有锁/CAS/拥有者线程处理准确交接；不复活旧对象、不误改新占位 |
| 旧代任务继续计算 | 拒绝它后续准确坏写入/结果发布，保留真实退出及后继结算；共享线程继续服务其他任务 |
| 某个动作失败 | 记录具体失败，继续不依赖它的准确步骤；不通过整链“资格不齐”停掉所有动作 |

### 4.4 写前拦截是功能，不是额外验收门

最常见 guard 只读已绑定对象的当前策略，决定允许还是拒绝真实变更；不做全图反射、同步刷盘、每次建 permit 或跨进程往返。共享 writer 的目标选择、实际变更与撤销用同一个短定序点；不能只在 HEAD 查完，换对象后仍照写。

准备/大块 I/O 在门外。已先于撤销提交的效果保持历史，撤销先发生就拒绝后续动作。合法重入仅放行当前操作的准确步骤，不能用全线程 bypass 让子任务继承免检。

### 4.5 结果检查后置，不能把失败改成成功

已返回保护激活后，非法原值写入、移除、坏包/帧等对应效果必须没有发生；发生后再恢复，就报告突破和修复。没有覆盖的必要路径明确报缺口，已有可执行动作继续。

既有 REQUEST_ACCEPTED、SESSION_GUARD_ACTIVE、DURABLE_POLICY_ACTIVE 等状态只用于如实输出，不新增状态机。未知恢复源和 OPAQUE 效果继续未决，不能为了输出“完成”删除它们。

### 4.6 写完整批，再集中测关键结果

沿实际生产入口把这一批写完整，中途只做必要编译排错；随后集中验证清除、防护、恢复源、合法邻居、换身/撤销及受影响的存储/资源路径。复用现有夹具和场景；没有代码变化、失败或范围变化时不重复跑同一组，不按每个 hook 发一轮报告/JAR。

测试查真实索引、原字段、业务效果和来源能否再用；生产不新增每动作 verifier。R3 新列的机制是现有组合的覆盖说明，不是开写前必须取得的几十张许可。

<a id="attack"></a>
## 5. 通用攻击

### 5.1 当前身体清除

生产流程必须真正执行以下必要动作，而不是只登记请求：

1. 绑定实际选择到的对象、所在世界、原字段身份和当前代码/载体；公开 getter 的随机回答不能改变目标归属。
2. **先封准确回填/执行/发布入口，再进行不可逆清除。** 同一 current strategy 覆盖旧身体回插、已证明源的结果发布及适用调度；不能把这些门的生效条件设成“本体已经 executed CLEAR”。普通 `remove/setRemoved` 是动作之一，不是唯一入口，也不能决定整条清除的最终权威。
3. 按对象身份检查所有当前适用的 ID/UUID 别名、Section 全表及类表、Tick 活动/备用表、Tracking、导航、多部件及关系边，执行准确清理。
4. 单独处理 callback、能力/资源以及必要的客户端传播。直接写移除标志不等于这些工作都完成。
5. 独立读取实际记录，观察后续真实 tick 和必要客户端。仍有任何适用身体义务，O01 不能完成。

生命归零、死亡语义、掉落/经验、当前身体清除可以组合，但不能互相冒充。目标自行实现额外生命源时，通用身体处置仍须推进；额外生命源和回调效果另行处理并保留缺口。

### 5.2 容器替换与直接回插

当前载体变化时必须有重新定位路径。解析至少检查：当前 realm/世界/管理器、准确对象、代次、定义加载器、容器实现及占用情况。

只向当前容器做定点操作，不把旧容器整包写回。槽位已被其他合法对象占用时，不因旧目标曾使用这个 ID/UUID 就覆盖它。能够按准确对象清理其他位置的步骤继续推进，冲突位置单独报告。

正常支持清单必须覆盖声明环境中的标准 HashMap/HashSet、ArrayList、对应 fastutil 容器以及其被换成新的同语义实例。自定义容器需要实际操作适配和版本条件；不认识的实现必须保留未决，不能永远只写“unsupported”却宣布基础完成。

旧对象重新插回、新身体重建、当前容器替换是三种情况。前者不能不断伪装成全新无关目标；后者不能仅靠类名或位置被归成旧目标。

### 5.3 入口与结果一致

清掉实际表之后，还要检查真实运行是否仍从静态对象、独立任务或其他入口继续使用目标。查询结果补入、额外渲染和实际物理登记分别检查。

不修改查询输出来“制造清除成功”。如果列表仍能返回由实际来源持有的目标，必须处理持有/生产入口或保留相应存在义务。

反射、Unsafe、方法替换等只是实现手段。优先复用少量可靠原语；只有确实覆盖新的绕过路径，才增加后端。

### 5.4 攻击默认从维持目标的来源和生效点动手

攻击并不是只把自己的 remove 调用提前。必须阻止目标防御/恢复路径继续产生合法结果：

```text
准确目标策略生效
→ 立即封住可确定的回填、委托/恢复入口与结果提交
→ 直接清本体/索引/关系和已确认内存源；持久及未知副作用按具体步骤分流
→ 在途结果拒绝发布；迟到任务/新身体按当前代次处理
→ 查清 actual exit、资源、保存和重启结果
```

有准确共享源时只切目标那条输入/输出边；不能让一个静态 manager 下所有生物都失效。没有足够 lineage 的部分不授权跨对象删除，但当前准确身体、已经确认的来源和结果入口必须继续执行，不能因全图未完成而一动不动。

**源终结和持续压制分别验收。** 保持 guard 时不重生，只能证明压制；测试暂停本次临时压制后，旧源不会自行恢复，才能给相应声明范围的源终结事实。独立召唤蛋创造无关的新目标必须仍可用，不能用全类型禁生成伪造源终结。

### 5.5 不让“更低层”变成重复无效动作

既有 raw removal/canUpdate、准确索引清理、关系解除继续保留，不能以“源会被封住”为由删掉基础拳脚。确实支持的反射/MethodHandle/字段写入适配集中复用；目标的同名 getter、方法空实现、事件取消和查询伪装不能否决准确原语。

允许在准确合同内给目标相关调用提供无效化完成，但必须遵守该调用的返回/异常/资源约定，不能破坏共享调用栈、吞掉合法 finally 或把未知副作用改成成功。清不掉哪条必需记录就保留哪条缺口，不能过滤自己的验证查询制造“查不到”。

<a id="defense"></a>
## 6. 通用防御

### 6.1 防御对象与生效状态

防护必须明确支持玩家和普通存活实体，不能共用攻击目标过滤条件而误拒绝玩家。多人、同类实体、跨维度对象和独立加载器分别绑定；只保护准确目标。

普通输出区分：请求已接受、当前会话 guard 已生效、持久策略已生效、防护缺口、已撤销。命令执行过不等于所有保护入口已经生效。

### 6.2 主防线、独立截点与事故恢复

| 能力 | 真实要求 | 不能代替它的结果 |
| --- | --- | --- |
| 前置阻止 | 在受支持的伤害、死亡、移除、字段或记录写入入口，阻止不符合当前保护策略的变更 | tick 末补血、死后重建、事后收到事件 |
| 受损修复 | 直接字段改写、删除登记、替换容器后，从当前合法事实恢复准确状态及必要执行关系 | 只恢复血条、只补一张表、把旧整个世界快照覆盖回去 |
| 持续完整性 | 实际 guard、callback、记录和关键入口仍有效；遭到替换后撤销错误的有效状态并恢复能力 | “钩子已注册”“保护开关为 true”“进程没崩” |

三项共用身份、策略和原语，不形成三套防御框架。**前置阻止是常态交付要求；持续完整性保证前置门不断档；受损修复只保证突破后可恢复。三者不是可互换的达标选项。**

### 6.3 必需覆盖

- 生命和死亡：普通伤害、直接死亡入口、直接生命写入、NaN/无穷值、最大生命来源、死亡计时/标志及本体状态。
- 物理存活：原字段 removalReason、canUpdate、callback、包围盒、当前 section、准确 ID/UUID、Tick、Tracking 及适用导航/多部件登记。
- 持续防护：非法效果、火焰、饥饿/状态、装备及防缴械、未经当前策略允许的传送和跨维度变化；合法变更继续可执行。
- 外部执行：实际线程/任务继续写回或清除时，识别准确生产者并处理其写入边界；不能为保护一个目标关闭共享线程池。
- 客户端：服务端保护结果对应到客户端实际身体/跟踪；陈旧移除消息不能覆盖当前合法新代状态，合法移除和断连流程不被一律丢弃。

不同入口的实现和观察各自登记覆盖。只拦基类方法不能代表所有覆盖写法、直接字段写入或 Native 路径已经防住。

### 6.4 直接改写后的修复规则

恢复依据是当前保护合同和最后有效的必要状态，不是每 tick 复制全部对象字段。

1. 确认仍是受保护的当前对象/代次；合法传送、重生、世界卸载、退出和解除保护分别处理。
2. 定位当前世界与容器，先发现合法占位、共享边及载体变化，再进行准确补回。
3. 修复原字段、callback 和登记关系的依赖顺序，保证实体恢复后真正执行、可移动、可追踪，不能只留下“活着”的对象。
4. 通过实际字段、索引、后续执行和客户端观察确认。其他对象、合法新装备/位置及世界更新保留。
5. 持续受到改写时，处理准确写入源并有界维护；不能靠无上限高频写回与对方永久空转。

若物品已经掉落、死亡统计/存档已写入、网络副作用已传播，恢复血量不能撤销这些事实。应按实际效果查询/补偿；不能复制装备或把发生过的死亡改成“成功免伤”。

### 6.5 防护成功必须区分两种结果

“本次攻击被拦住”要求受保护条件未被破坏，相关不可逆副作用未发生。“受损后恢复”要求实际恢复并交代中间损失。

两者都可以是有用能力，但后者不能替前者通过免伤/防移除验收。持续防护需要连续干扰场景；20 tick 完成窗口不是允许目标先死亡的缓冲时间。

### 6.6 直接字段与容器变更的必需前置覆盖

补丁应首先作用于已经确认的实际 writer 和共享关键变更点，而不是全局改写所有 Java 集合或每 tick 回填：

| 绕过方式 | 必须增加的真实截点 | 必需反例 |
| --- | --- | --- |
| 子类覆盖方法、不调用 super | 实际生效方法/调用者的具体副作用点，以及共用最终状态写入 | 基类 guard 在场但子类绕过；不能只测 super 路径 |
| DataItem.setValue / 原字段写入 | 实际数据项身份、字段 owner/descriptor、写入对象和代次前置检查 | 绕开 SynchedEntityData.set；非法值不进入原值槽位 |
| Map/Set/List/fastutil/迭代器/视图写入 | 在受保护 backing store 的真实 mutation 或其已登记调用点执行准确拒绝 | remove/clear/values/removeIf/entry.setValue、别名、同键不同对象 |
| manager、lookup、callback、整容器换指针 | 字段发布前对新 carrier 与当前策略做原子交接或拒绝 | 同语义新实例、上层 manager 更换、合法迁移、不完整新容器 |
| 反射/MethodHandle/VarHandle/Unsafe | 对声明受支持的具体 writer/调用点和可控制结果边界独立覆盖 | 不能因 java 层 setter 已守住就宣称所有直接写法已守住 |
| Native 原始写入 | 仅据真实后端可控制的具体入口认定；无前置能力则明确缺口 | 观察回调/事后写回不计 veto；不伪造“任意内存不可写” |

本表是实现要求，不声明本包已具有这些转换。JVMTI FieldModification、类字节指纹、Accessor 本身并非万能写屏障；对应技术事实见 [平台依据](平台依据与实现边界-V1.4.md)。

### 6.7 保护不可因线程、排队与重装而失效

- 从合法激活点起，服务器线程、池线程、事件/委托回调的已知受保护写入都读取同一个已发布策略。不能继续用 `isSameThread()==false → 无 runtime → 放行` 作为实际 guard。
- 捕获事件排队、计数器满、日志 ACK 慢不得影响已发布拒绝策略。阻断使用同步短门；重型观察和结算走后台，不用扩 inbox 代替时序修正。
- 门切换/重转换时旧门或另一个独立有效截点必须覆盖该结果，直到新门真实生效。只暂时清空保护、稍后重新装好，属于保护空窗。
- 不能简单停住整个 JVM/共享池来声称无敌；无关主体、玩家合法移动、传送、退出、解除保护必须有进展。
- 无法兑现某个必需入口就报告缺口/激活失败，并保留其他准确保护。不能把被保护对象先杀掉或全面冻结来通过无损正例。

### 6.8 先拒绝破坏，恢复不再是默认战斗循环

常态验收：首次有害字段写入、首次记录移除、首次错误网络/渲染发布都不得发生。将 `maintain()` 暂停作为仅测试扰动，前置正例仍应成立；测试不向生产注入身份、来源、许可或结果。

事故恢复另测：人为绕过已声明覆盖制造破坏，记录 breach，检查原字段/登记/资源准确恢复和真实损失，随后重新验证前置门。该结果不得覆盖同次前置失败。连续“删了再补、死了再活”不是本版最高防护。

<a id="recovery"></a>
## 7. 来源、重建和准入

### 7.1 来源从内存真实存在时开始

最小支持面包括：

| 载体 | 必须具备的通用路径 |
| --- | --- |
| 静态字段 | 直接 Entity/记录引用、标准集合及嵌套包装；依据真实对象关系和定义加载器关联 |
| SavedData | 实际缓存 holder、首次写盘前的记录、标准 Map/List/Set、对象字段内快照及辅助状态 |
| 任务/回调 | 实际提交、委托、父子、周期重排、继续执行及后到回调持有的来源 |
| 构造/工厂 | 实际输入记录、创建动作、产生的对象及最后登记之间的关系，包含没有 Entity.load 的路径 |
| 保存/通信 | 真实读写/分派触发的重建，绑定保存代次或会话/目标代次 |

HashMap 包装记录和构造器创建新 UUID 是必需的基础恢复场景，不能只使用直接 CompoundTag 的 ConcurrentHashMap 或 Object.clone 代表全部重建。

### 7.2 发现不等于允许删除整个包装对象

发现以只读、有界遍历及真实生产入口观察为主。执行前必须知道移除的是哪个准确条目、谁持有它、与哪些目标共享，以及容器在实际写入时的并发规则。

包装记录里包含一个目标快照，只能证明存在关联，不能自动授权删除其中其他实体、共享计时器或资源。应优先处理准确目标边/子记录；整条记录确属目标时再整体处置。未知字段和其他条目保留验证必须包含包装层。

普通 HashMap 不能因“在服务器线程看到过”就被宣称线程独占。实现须明确实际读写入口、锁/线程域或其他受支持并发协议；并发替换负例必须通过。发现路径不能反过来伪造这种资格。

### 7.3 无 NBT 重建的关联

建立通用 producer 观察：实际记录读取、任务/工厂输入、对象产生和最终登记；支持的路径以真实数据关系关联输入与输出。

同一线程、相近调用栈、同类、同位置、相同内容或相同 UUID，都不足以单独建立 lineage。共享 producer 为不同目标产生对象时，必须保留每次准确输入/输出的区别。

来源关系明确后，新 UUID 不解除旧主体的终结策略。关系尚不明确时，旧准确身体和已绑定来源仍继续处理，新对象保持未决，不按类型误杀。

### 7.4 准入与源处置并行推进

前置拒绝原对象回插、关闭准确重排入口和处置持久恢复记录互相配合。阻止一次登记不等于来源已经结束；删除内存快照不等于磁盘和正在执行的任务已经结清。

新来源、包装字段变化、保存代次变化和代码替换必须使当前完成失效。没有首次保存、没有捕获事件或工作列表为空，都不能当作“没有恢复源”的证据。

### 7.5 “产生之前”与“进入之前”的准确界线

已准确绑定本次 producer 的输入/目标时，在工厂调用或源消费前拒绝，不必为了获得一个新对象再允许整段业务执行。只有输出才能确认身份的路径，应在其第一次危险发布之前验证；构造函数已经产生的全局副作用不能假称被后来 Admission 撤销。

`NEW`/构造调用涉及对象初始化，不能随意在 JVM 任意 `<init>` 指令中返回 null。应选择有效的工厂/委托边界或经过验证的创建协议，保持异常、初始化和资源合同。源码的 Object.clone hook 只是一个具体路径，不代表构造器/工厂全覆盖。

新 UUID、新对象和换容器都不得独自撤销已证明的目标关系；同类型、同位置、同线程和相似调用栈也不得独自创建这种关系。广度靠真实 producer 输入输出覆盖，不靠类型黑名单。

准入控制必须检查到实际 manager/索引/队列/镜像提交：禁止先进入一个可被读到的集合，再在 joined/tick 中补删。短时滞留的私有候选若确有合同可行，须不可运行/不可观察且有时限及资源归属；它不是把目标放进世界。

<a id="durable"></a>
## 8. 任务、资源、保存与重启

继续复用已经存在的通用实现，不另造一套 B 日志体系。

### 8.1 任务及后继

覆盖普通 Future、定时/周期任务、ForkJoin、CompletableFuture、实际委托包装和迟到后继。分别记录取消请求、取消返回、实际进入、实际退出、周期重排及后继闭合。

排队任务可以用实际 `START_PRECLUDED` 闭合，不等待不存在的退出回调。运行中任务即使取消成功，也必须有 `EXIT_OBSERVED`。父任务退出不能清偿子任务；已完成 Future 的结果仍可能持有恢复来源，不能因任务终态丢掉结果资源。

工作线程有界捕获，服务器线程合并；任务、父子关系、来源资格和定义加载器分别绑定。共享池不关闭，共享工作线程不粗暴中断。

### 8.2 资源

统一记录任务句柄、队列/等待者/后继引用、目标记录关联票据、共享持有份额、候选缓冲、Native/事务句柄和 reservation。解除本操作的引用与释放共享资源本体分开。

实际释放后才登记事实。弱引用消失、取消返回、关服和仅做引用探针不能代表释放。有限活动缓存只移除缓存，未结义务保留并公平轮转。

### 8.3 实际保存与提交

SavedData 与静态来源使用同一协议。从实际保存流的文件句柄捕获身份，关联真实编码、来源、保存代次和保留证据；路径或候选字节不能直接换取写权限。

沿用运行时可用的 Windows 本地 NTFS/TxF 首后端合同：事务内复验原文件和基线、写完整候选、验证事务图像、共同提交门内复验并提交、重新独立打开读取。后端不可用保持明确未决，不回退普通覆盖并宣称同等保证。

区分未执行、已确认回滚、提交待查证、已提交和效果未知。Native 返回成功不等于恢复链完成。目标处置与其他条目/未知字段保留一起验证。

### 8.4 重启与版本

从原意图枚举未结工作；按已登记来源重新定位 holder、代码版本、文件身份和保存代次。未加载来源保持等待，不扫描任意第三方文件，不复用旧指针和旧许可。

读回匹配预期图像及完整保留条件才登记当前事实。基线未变也不能直接重放：先确认旧事务不再可能提交，再取得当前资格，沿原 key/attempt 接续。未知效果不能换操作 ID 或后端绕过。

V1.4 是设计版本，**不自动升级运行时 schema**。实际新增持久语义时集中版本化；旧 command、hash、ONCE、attempt 和未知效果原义保留，未来版本拒写。

### 8.5 任务从首次执行前拒绝，后台合并只负责结算

复用 TaskBridge 的真实 invocation/fence 和 RecoveryTasks 的退出/队列/资源结算；ACK 只约束 §4 确需持久接续的步骤，不挡准确启动前拒绝。新增要求：

1. 已发布准确终结/保护策略的 0 延迟任务，提交/委托/worker enter 路径同步取得最小来源与当前拒绝决定。不能把“等服务器每 tick 合并事件再 cancel”称作启动前阻止。
2. 后台图尚未齐时，不猜 task 与目标的关系；但 task 的准确写入/注册/发布若命中受保护对象，最终门仍当场生效。源级提前终结与结果级无效化分别计数。
3. 未启动任务的拒绝要有真实 START_PRECLUDED，同时处理其调用者看到的取消/异常/完成与 reservation；不能早退 leave Future 永久 pending。Shared callback 只阻止本次已绑定调用，不能冻结共享对象全部用途。
4. 已进入的 task 不靠强行停线程“消失”。准确相关写入/提交及新后继被门挡住，当前 frame 真实退出后再计 EXIT_OBSERVED。重转换对旧活栈的限制见 E01。
5. 权限/代次撤销、并发重排、桥重装、队列溢出期间，已发布 gate 保持本对象约束；事件不足会阻止完成结论，不能自动取消有效拒绝策略或毒死全部无关图。

### 8.6 保存和资源必须在不可逆动作前截断

自有 Native finish0 的提交前门继续复用。第三方业务保存还须单独控制 **打开并截断原文件之前** 的准确写入：生产 `RecoverySources.open()` 当前主要捕获身份，不等于拒绝非法写入。

持久目标旧代结果、错误文件身份或不被授权的候选不能先写入真实基线再纠正。合格候选可先在私有暂存/事务内准备，直到最终门后才获得外部效力；拒绝不能留下损坏原文件、半发布句柄或共享资源已释放。

这不意味着阻断所有 NBT 保存：合法无关文件、同文件其他记录、受支持共享 writer 与未知字段仍保留。跨对象和外部事务按既有 HARD 纪律，不扩大 scope。读取旧存档恢复目标时，在实际 load/注册/发布处拒绝已失效结果；重启后的 guard 要在相关世界工作暴露之前建立，否则只能报告启动缺口。

## 9. 世界、运行时、Host 与视觉

本轮先补通用攻防，以下完整 Pro 目标继续保留：

- **World**：BlockEntity 自身记录与 ticking、方块/区块/区域、射线和范围、传送、时停/禁生成、全字段与引用图、世界历史恢复、种子重生成。历史恢复与重新生成分别验收。
- **Code / Runtime / Integrity**：实际加载器、基类/覆盖方法、Mixin/ASM/Javassist、ModLauncher、反射/MethodHandle/Unsafe、Instrumentation/JVMTI、JNI/Native、事件总线/handler、方法和字段语义、真实返回与反拦截。
- **Host / OS**：自动取得或复用已授权高权限执行、使用/安装驱动、模块准入、进程/子进程/线程控制、读写执行权限、异常映像、注入响应、常驻生命周期及恢复。能力目标、实际后端、平台授权条件分别列示；不是本次文档制作中的系统操作。
- **Client / Presence**：服务端 tracking、客户端镜像、HUD/BossBar、纯渲染对象、包/输入、required/optional 参与者、断连和重连。画面不代表全部世界状态。
- **视觉**：现有 Ronova 主题、主图、剑内效果、Tooltip、光柱与标题界面、关闭回退、发光第三视角遮罩和资源重载。复用已有成果，视觉不计作攻击强度。

用于基础攻防的实际覆盖方法/分派控制、限定对象的代码防御剥离/返回控制与反全返回、准确回填 producer 的控制、必要入口连续性都在 A 成批实现；不是只把完整性检测提前。C 完成全面运行时、Native/Host 和其他完整控制面，不能反过来成为 A 已声明战斗路径的必需缺件。详见 §3.4 与 §12.1。

Pro 不设兼容/强化/极限三档强度。Backend Selection、Fail Policy 和同合同后端替换只控制执行方式；不能静默降低能力合同。高权限状态需报告当前权限、请求结果、实际执行权限与失败原因；提示或加载成功不代替实际效果。系统授权条件不被“自动”一词取消。

### 9.1 全部控制面统一使用前置标准

**World**：区块/BlockEntity/ticker/传送/区域写入在实际状态或登记发布前控制，历史回滚与种子重生成仍是不同 HARD 动作；不能先毁坏边界外世界再回滚。

**Network/Input**：在准确连接/会话/请求代次和 handler 的首次业务副作用前拒绝；在途包在实际世界/镜像写入门再核验。合法断连、移除、重生和玩家输入不能被全局吞掉。拒绝旧包无需等待客户端先丢身体。

**纯渲染/Presence**：实体是否入世界列表不是唯一发现依据。对目标真实绘制回调、资源与持有关系，在登记和目标 draw 发布前阻断；已提交上一帧只能清理，不能追认未渲染。共享 batch 中要只去掉准确目标份额，无关画面继续。客户端未参与时不宣称远端任意画面已控。

**Code/Runtime/Integrity**：基础所依赖的实际 writer/回调/定义要在首次相关调用前建立控制；转换后字节、实际分派和旧活栈分别考虑。Mixin HEAD/高优先级 Event 不是覆盖全部 writer 的保证；关键 gate 本身的策略读取与依赖也要有真实保护和版本交接。只发现被改再恢复，是事故路径。

**Host**：保留已授权高权限、驱动、模块/进程/线程与访问控制目标；实际可拒绝的访问/执行边界才算前置，加载通知、事后终止/卸载、事后改 ACL 不得冒充。只在真正选用后端时展开安装、签名及升级工作；不能为了列能力提前堆外围工程。系统授权条件、明确目标范围和可卸载性仍保持，不能通过破坏系统或无关对象赢得验收。

**资源压力**：相关分配/重复调度在受支持分配或进入队列前背压，不能故意等 OOM 再自愈。私有负载的阻断不连带共享 JVM 合法工作。Visual 功能本身不计攻击强度，但资源重载不得造成门消失的空窗。

## 10. 结果与稳定完成

### 10.1 既有五类 Outcome

| 结果 | 必须满足 |
| --- | --- |
| O01 当前身体清除 | 准确身体及所有实际适用的身体、索引、tick、关系、tracking/presence 义务满足 |
| O02 恢复链终结 | 声明范围的发现覆盖、内存、存储、任务、后继、资源、必要 ACK 和未知恢复效果全部闭合 |
| O03 存在终结 | 身体、世界记录、旧代拒绝、恢复任务、重建入口、保存资格、tracking、服务端存在及未结工作满足完整合同 |
| O04 最终结果接管 | 实际分派及 RETURN/THROW/ABORT/SUPPRESS/REWRITE 的返回合同和副作用范围满足 |
| O05 持久收敛 | 声明持久范围的原意图、外部图像及必要效果经保存、独立读回、重启后继续成立 |

防护结果直接检查其前置阻止、修复和持续有效的后置条件，不新增一棵防护 Outcome 类型树，也不把防护成功写成 O01。

### 10.1.1 防御与拦截的时间事实

前置成功以效果点为界：`activation ≤ reject < first_forbidden_effect`；若能独立确认该效果未发生，可计对应前置结果。零泄漏是“没有发生”，不是测量出 0ms 的短暂泄漏。并发时使用可证明定序关系，不只比较不可靠的跨线程日志顺序。

实际已发生有害效果，即使同 tick 内恢复，也记 `BREACH` 和可能的 `REPAIRED_AFTER_BREACH`。O04 的无效化只有在相关外部效果全未提交时成立；改返回值不消除副作用。O01/O02/O03/O05 的现有事实合同不被这个时序规则删除。

前置防线可已生效而 O02 尚未完成；guard 提供压制不等于源终结。新源/新代出现撤销完成判断，不应自动撤销仍对准确旧目标有效的阻断。

### 10.2 覆盖先于稳定计时

存在实际相关但尚未纳入执行的 holder、包装记录、任务或已知不支持入口时，O02 不进入完成窗口。未扫描、未加载、未写盘、预算不足和事件丢失是缺口，不是 N/A。

稳定窗口继续 **20 tick**，最大采样间隔 **10 tick**。新来源、任务、回插、载体/资格/保存代次/代码变化和证据过期立即撤销当前结果；历史回执保留。

20 tick 是满足条件后的稳定观察，不是证明所有未来定时器都不存在。必须有 60 tick 及更长延迟重建、跨重启延迟触发的反例；不能将窗口简单加长来遮住未发现的来源。

同一候选的静态、动态、客户端和持久范围分别声明。已知范围完成不能宣传为所有未知实现都已终结；必要正例未通过时，强度交付仍未通过。

### 10.3 普通输出

- 身体已清除 / 身体仍存在。
- 重建已阻止 / 恢复源仍待处理，并给出主要原因。
- 已知恢复链已处置，仅在 O02 满足时显示。
- 本次攻击已拦住 / 受损后已恢复 / 防护存在缺口。
- 策略已撤销；历史效果仍可查询。

必要客户端断连属于 UNKNOWN，不能改为 NOT_APPLICABLE。纯呈现目标不制造不存在的 Entity 义务；有 Entity 的目标也不能临时改成纯呈现以跳过身体检查。死亡、掉落等 OPAQUE 效果不因其他 Outcome 成功而被改写。

## 11. 预算、体积与性能

- 同步前置 guard / 最终无效化门优先；准确修复是事故后独立调度；存储 ACK 和观察队列不能成为已激活防线的放行条件。
- 使用已观察入口、当前对象索引、版本变化和脏标记唤醒，不对每个实体每 tick 反射扫描全 JVM。
- 来源/图遍历、任务事件、候选和活动缓存有界；超限必须保留可见缺口和可恢复调度，不能丢义务或长期高频空转。
- 同一依赖版本的重复观察可以合并；实际新来源、新代次及未知效果不能被合并掉。
- 热路径不做同步持久 I/O。已有初始性能目标保留为待测目标：固定负载 tick p50/p95 增幅不超过 5%、p99 不超过 10%；后台总预算初值 2 ms/tick、恢复维护配额初值 0.5 ms/tick，按实测调整。
- 单独记录请求到 guard 激活、首次拒绝、实际前置穿透、首次修复、最长保护空窗、源处置和持久完成；目标值为受支持已激活范围 forbidden_effects=0、wrong_target_blocks=0、repair_used_for_prevention_pass=0。p95 修复快不抵消任何一次穿透。
- 修复型保护的支持合同须给出最大恢复延迟；初始目标是在下一个允许安全写入的服务器维护点恢复。超过该点仍未恢复即登记失败，不能借预算等待继续称防护有效。
- 记录 Core/Agent/Bootstrap/Native/客户端/素材/依赖与全安装体积，检查重复依赖、空包装层和每次动作分配。类数只作诊断，不作为强度或体积的替代指标。

前置阻止型保护不能有“允许先受损一个 tick”的豁免。无法在预算内维持必要条件时如实报告能力缺口。

<a id="zero-args"></a>
## 11.1 玩家免 JVM 参数启动

**交付要求：玩家将发行 JAR 放进 mods，用支持版本的 Forge 正常启动；不手填任何 Ronova 专用 JVM 参数。** 这项已经由用户确认，不是可选优化。

不要求玩家填写 `-javaagent`、`-agentpath`、Native DLL 路径、`--add-opens`、`--add-exports`，也不要求替换 Java、手动运行辅助脚本或修改启动器 JSON。开发模式可以保留显式参数用于诊断，但不能以开发启动方式完成玩家入口验收。

### 打包和加载

1. 玩家默认发行入口为一个 Mod JAR，包含所选平台所需的 Core、早期引导、最小观察桥及 Native 载荷。开发阶段的 Agent/Bootstrap 分包是内部构建产物，不转嫁给玩家配置。
2. 在支持的 Forge/ModLauncher 早期加载阶段建立必要入口；需要 JVM/Native 边界的部分使用实际可用的自动引导后端。必须先证明后端可行，不能在文档里把现有 `premain` 改名就视为已实现。
3. 对必须写到磁盘才能加载的自有载荷，按版本/摘要提取到 Ronova 自有缓存目录，检查完整性后加载；处理并发启动、Unicode/空格路径、文件锁和升级。不能覆盖其他 Mod 或系统 DLL。
4. 若支持后端需要临时辅助进程，由 Mod 管理本次启动、身份和退出，只服务当前 JVM；失败、超时和异常退出可见。不能留下未说明的常驻进程或修改全局启动配置。
5. 核对实际类加载器、代码版本、Native ABI、观察桥、模块访问和必须的原语入口。核心 Mod 被发现、DLL 加载返回成功，都不足以证明完整启动。

### 启动完整性与失败语义

- 在相关功能显示可用前，完成所需引导和实际入口自检；观察器尚未安装时不得先接单并把缺失事件当作没有任务/来源。
- 已经发生的早期活动不能靠晚装观察器补成完整事实。晚到引导必须有受支持的重新定位/补观察路径；否则保留启动覆盖缺口。
- 禁用动态加载/附加、缺模块访问、Native 不匹配或加载失败时，显示确切原因和受影响能力。不得静默切到只加载 Core、仅观察或更弱的合同，却显示“Pro 完整可用”。
- 首个支持组合必须实际做到免参数启动；不能把所有真实环境均记为 UNAVAILABLE 后宣布这项完成。确实不支持的环境保持条件声明，不虚构万能加载方式。
- Host/驱动等平台组件的安装和系统授权条件单独列出。免 JVM 参数不代表绕过系统授权；拥有已安装后端时应自动发现并使用，不让玩家补 JVM 参数。

### 必跑验收

使用干净隔离启动器配置、正常 Forge 入口和发行 JAR，确认**用户没有手填** Ronova JVM 参数。内部自动受控启动若必须带 premain/bootstrap/Native 参数，只记录 Ronova 管理的参数白名单、来源、ABI 与交接结果；认证令牌、会话秘密和其他私人启动参数不得原样写日志，也不以其完整命令行摘要充当证据。不以“玩家无参”伪称“进程绝对无参”。用户可见入口不增加配置步骤，Core/Agent/Bootstrap/Native 仍须匹配。

当前 RecoveryAgent.agentmain 明确拒绝晚附加覆盖，因此免参引导需证明实际早期安装或受控交接可行；不能仅重新命名 premain。业务暴露前检查真实能力，随后运行攻击、防御、任务/来源、Native 保存和重启接续。

同时覆盖二次启动、版本升级、同机两个实例、目录含中文/空格、提取目录不可写、载荷校验失败、缺失后端、启动中断以及晚装观察边界。失败测试不得依赖夹具帮忙装 Agent 或传入最终成功证据。

免参引导的可行性和最小实现提前进入 A 返修批次；B 所需观察/存储能力也必须从同一玩家入口启动。最终验收不能继续只用手动 `-javaagent` 的隔离服代替。

R3 的首选实现路线是发行 JAR 的 Forge/ModLauncher 可用早期入口，自动加载匹配的最小自有桥，先准备所需定义/分派/写入门再开放相关功能。Secret 的 Mod 静态初始化仅证明一种构造前加载写法，不证明这一时点覆盖 Ronova 所需全部早期任务。若首选路线缺少必要能力，受控交接后端只有在同一玩家入口中确实维持单一游戏 writer、完整观察及失败恢复时才可替代；不盲目轮试所有注入方式，不把现有 agentmain 拒绝逻辑改成成功即宣称补齐历史。

### 11.2 最小观测，不再造一套证明系统

每个现有 operation 的诊断按需带：截点、源/目标/代次、真实 attempted 次数、rejected 次数、非法实际效果次数、修复次数、未覆盖原因、激活/撤销 revision。静态覆盖表和独立场景断言复用，不为每个计数器新建 Evidence 类。

关键统计：`entry_denied`、`write_denied`、`publication_denied`、`forbidden_effects`、`repairs_after_breach`、`wrong_target_blocks`、`inflight_at_activation`。名称可沿项目代码风格调整，语义不可混合。source 图完成前仍能精确拒绝已知写入；日志掉帧只使诊断不完整，不能导致策略默认放行。

### 12.4 本次强化的强制否决条件

下列任一现象出现，即使回满、重新插回或最终清走，也不得通过相应前置正例：

- 已报告 SESSION_GUARD_ACTIVE，但保护必须等一次 ACK 或下一次 END tick 才开始。
- 服务端池线程执行同一非法写入直接绕过保护；对方写入发生后才排队给服务器修。
- 目标新身体先进入 Lookup/Section/镜像或跑了恢复 callback，再通过原样清除把日志刷绿。
- 仅保护基类普通方法，声明必需的直接字段/集合视图/上层载体发布仍可破坏状态。
- 0ms 新任务先执行，随后取消并用无副作用样本掩盖；暂停 tick merge 就完全无法阻止已确认目标的效果。
- 原文件先 truncate，之后回滚或覆盖成正确内容；错误 draw/包先提交，然后重同步。
- 突破计数由生产的同一返回 flag 自证为零；检测代码使用被过滤的查询而看不到真实残留。
- 否决了无关实体、玩家合法交互、共享池或整个系统，靠扩大目标范围制造“打不到”。

详见 [前置阻断验收合同](前置阻断验收合同-V1.4.md) 与矩阵机制子用例。R3 不增加父/子用例编号、runner 或生产验证层，在原组合内补实际别名、批量操作、派生、拆门与 Native/Host 对照；实施仍为整批代码→集中关键验收。
