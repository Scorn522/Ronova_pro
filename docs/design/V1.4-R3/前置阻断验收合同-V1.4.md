# V1.4 前置阻断验收合同

修订：R3（2026-09-20）。**DESIGN_ONLY / NOT_RUN**。本文件不新增 Outcome、不新增 Executor，也不把子用例数量变成能力计数。对应主设计与能力矩阵共同使用。

## 1. 什么才算“对方打不到，或打了无效”

必须区分入口、状态写入、结果提交三个事实。把日志放在函数 HEAD 不自动证明动作未发生，方法返回 false 也不自动证明无副作用。

| 可报告事实 | 独立验收内容 | 不能混入的结果 |
| --- | --- | --- |
| ENTRY_REJECTED | 准确目标相关的本次调用未进入实际副作用代码 | 进入后取消、异常中止前已产生效果 |
| WRITE_REJECTED | 原字段/容器/slot 从未接受不合法变更 | 下一行或同 tick 写回原值 |
| EVALUATED_NO_EFFECT | 计算可发生，但非法结果未进入任何 required 状态/登记/磁盘/网络/图形/资源出口 | 丢最终返回值但死亡、掉落、存档或 callback 已发生 |
| REPAIRED_AFTER_BREACH | 独立看见破坏与随后实际修复 | 把它改写成前置免伤、拦截成功 |
| UNPROVEN | 缺少真实截点、范围或观察 | N/A、false、成功 |

时间关系以真实效果为界，不靠日志排序：激活定序之后的非法效果不得发生。对激活前已在途动作，若写入与撤销共同定序为先发生，保留真实事实；若结果提交在当前门之后，则必须受新规则约束。旧 stack frame 不会因 retransform 自动消失。

**防护无需等待识别攻击者。** 已绑定的受保护目标及具体非法变更已经足够作本地拒绝判断；来源图不齐只影响向上游攻击和整链完成。攻击也不因无关来源未发现而暂停已有准确身体与回填边的执行。

## 2. 测试不能用生产自己的成功位自证

通用 driver 只执行普通业务、攻击变体和故障/时序扰动。不得直接填 production source、generation、permit、event、ACK、graph、root 或 receipt。

观察点放在已定义业务副作用的真实消费者、持久文件和客户端结果上；读状态尽量使用原字段/真实容器，不能使用会过滤被终结目标的展示查询。只读诊断适配不建立资格，也不决定是否通过。

最小证据分为四组，允许按当前字段风格命名，不为每组新建类：

- 确认攻击尝试发生：attempted>0，真实 writer/边界、准确对象/代次以及同批未保护对照。
- 确认不产生非法效果：原值/记录、死亡/掉落/统计、回调、发布、磁盘或实际帧中的适用事实；不只是一个 wasCancelled 标志。
- 确认没有借修复过关：暂停后置 maintain/repair 的独立轮次，repair_used_for_prevention_pass=0；故意越过声明支持面的事故轮次另记 breach/repair。
- 确认没有扩大误伤：同类型无关对象、共享 manager 条目/线程池/callback/资源、合法退出/跨维度/重生及解除保护仍有进展。

不是每个动作必须生成所有日志。**代码少、断言硬**：一条通用驱动可复用这些检查，多机制用参数组合，不能为了打印字段另造观察/证书子系统。

## 3. 两种关停开关，不能弄反

**前置防护验收**：暂停“事后修复维护”，仍保留真实前置门、策略和普通业务攻击。确认无穿透。测试开关不进入发行普通玩家路由，也不提供权限绕过给攻击者。

**源终结验收**：在所声明旧源完成后，暂停仅用于该旧源的“临时压制门”，继续观察实际业务及迟到/重启恢复；旧源不得自行复活。永久终态仍存在却一直阻止发布时，只能证明持续 enforce，不能据此证明物理源已被处置。

两种实验目的相反：一个隔离修复，一个隔离压制。不得同时关掉所有执行器，再把结果归因于任意单模块。共享来源只对本次目标份额做实际处置。

## 4. 无损不是“最终看起来正常”

以下现象都计前置失败：死亡后复活、掉落后收回、索引空过一瞬再补回、非法 UUID/ID 映射被其他读者看见、先发错误移除包再重同步、坏 draw 已提交后下一帧恢复、文件截断后 rollback、Future 曾 ENTER 但后面 cancel 很快。

`EVALUATED_NO_EFFECT` 允许无外部效力的私有计算，不能把共享世界上的试执行叫私有暂存。以调用的具体副作用合同判断可撤销性；线程内、幂等或可以 fence 后续，不自动意味着历史副作用可恢复。

## 5. 容量、启动、并发不得制造常态空窗

同步短门不等磁盘 ACK、tick 合并或溢出的观察 inbox；缺观察使完成结论未决，不使已授权拒绝策略默认放行。故意暂停合并用于检验这一点，不注入伪造事件。

保护 activation/release、当前载体替换和实际变更共享明确的定序关系；禁止只 HEAD 查一次再把已经撤销的操作提交。门内不跑文件 I/O、第三方回调和全图扫描。

内部自动加载满足玩家不手填参数，但实际 premain/bootstrap 何时安装必须记录。晚附加不补写不存在的历史，bootstrap/Native/代码版本不匹配不能返回完整 ACTIVE。

## 6. 覆盖与交付

## 6.1 R2 不扩用例，只明确前移范围

A/C 或 A/B 不是“先记观察，实际执行随便拖后”。矩阵 §2.1 指定 A 当批必须具备的代码/分派/返回控制、包装目标边实际处置、任务源/工厂控制、玩家位移、UI/镜像/绘制能力；全面范围仍由 B/C 完成。已有 C25 父项纳入 A 组合，复用 C01.b/C26.c/C27.a 的实际入口与结果，不新增 C25 子编号或四套验证器。

C03.g/h/i 复用原测试配置核查：目标 raw 身份或载体字段暂时损坏时，已绑定策略不能因找不到 runtime 失效；合法交接另查。C01.b/C35.a 在原机制组合中保留不透明回调失败与独立准确动作的差别。C04.d/C05.c/d 不允许只读扫描或永久 gate 代替准确源处置。C23.a/C24.a/b 合并检查本批 UI/输入和实际画面，不能用客户端查询探针替代。
