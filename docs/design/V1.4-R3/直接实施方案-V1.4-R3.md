# Ronova Pro V1.4 R3：先把通用攻防做强

日期：2026-09-20。**方案稿，源码暂停；没有新 JAR、编译或实机通过结论。**

## 1. 这次怎么改

以 `D:/桌面/ronova` 当前 WIP 为基础，保留已有直接索引操作、任务观察、Native 存储和重启代码，重写拖住攻防的调用顺序和缺失入口。目标是小体积、短热路径、实际有效；原来清不掉、防不住的问题仍然是未解决的失败。

普通内存攻防不再统一等待完整溯源、持久 ACK、单独许可和下一 tick。**实际对象明确，就直接做能做的动作；结果检查在后，整链结算继续推进。** 写盘、Host 操作、跨重启权威和不能安全重复的未知副作用才保留必要原意图。

不再新建一套权限框架、验证器体系或每动作回执层。对象身份、当前策略和必要并发检查直接复用现有结构。写入前拦截属于实际防御功能，会保留。

## 2. 攻击怎么写

```text
命中准确对象
→ 立即禁止已确认的回填和再发布
→ 直接清真实身体、索引、关系与呈现登记
→ 剪掉已确认内存恢复记录和委托份额
→ 继续处理迟到任务、剩余来源、保存与资源
```

### 直接清真实状态

从实际对象身份取得当前载体，不让目标覆写的 `remove/hurt/getHealth` 决定能否清除。直接处理适用的原字段、Lookup、Section、TickList、Tracking、乘客/载具、Multipart 与其他准确登记。BlockEntity 用自己的 ticker、区块与登记路径；纯渲染目标用真实绘制登记，不伪造 Entity。

对方普通回调抛异常、空返回或取消事件，不得阻断其他独立的直接步骤。某一步是否执行未知，就单独查该步；不能让全体动作停在“资格未齐”，也不能因此宣称死亡、掉落等未知效果已经完成。

### 同批打恢复来源

已确认的静态 holder、SavedData 包装记录、工厂输入和任务委托，直接处理目标份额。共享容器保留其他记录；代码已经能准确识别的恢复调用，在进入或第一次结果发布前拒绝。无 NBT、普通构造器、新 UUID、换包装、0ms 回调必须进入这条实际链。

准确当前身体的清除不等整个来源图齐全；未知来源继续追，当前完成状态如实保持未决。持续压制与源实际删除分开：释放临时压制后旧源不能再恢复，才能算源已处理。

### 方法被架空时仍能执行

接管本批必需的真实调用、分派和结果路径；基础所需的覆盖方法、调用者 writer、EventBus 委托及 Native 边界一起接上。共享方法按本次对象/调用选择分支，合法对象继续原逻辑。不给目标整类套固定返回，也不把整个事件系统停掉。

## 3. 防御怎么写

保护请求在当前已安装入口立即生效，服务器线程和 worker 都读得到。查询已绑定对象的保护策略不再依赖可能被破坏的 raw level、UUID 或 getter。

主要拦截位置：

| 对方动作 | Ronova 实际动作 |
| --- | --- |
| 改生命、最大生命、同步数据、死亡/移除状态 | 在对应真实写入前拒绝非法变更，合法状态变化继续 |
| 绕 setter 写字段、DataItem、支持的反射/句柄/CAS | 把本批必需门放到真实 writer；仅守基类 HEAD 不算完成 |
| 删除 Lookup/Section/Tick/Tracking | 控制真实 backing slot、视图和迭代器；直接删表路径也生效 |
| 替换 Map、manager、callback 或玩家身体 | 非法发布拒绝；合法换维度/重生按当前身份交接 |
| 排任务或迟到回调继续攻击 | 准确任务进入/派生/提交受控；运行中任务后续坏结果不能发布 |
| 破坏本方必要门、关闭句柄或图形资源 | 在真实拆除/释放入口处理，合法退出和资源重载照常完成 |
| 发旧包、移除镜像、遮 HUD、提交错误 draw | 按准确会话/目标/资源份额拦实际发布与消费，保留合法包和同批其他绘制 |

维护补回作为防线失守后的恢复。停掉这部分修复后，已经声明覆盖的保护仍须成立；不能用 getter 固定返回或快速补血掩盖原值被改坏。

## 4. 底层推进到哪里

**第一批就使用必要的 Native 能力。** 早期自有桥、受支持 Java native 方法绑定与必要调用代理、关键资源的真实控制，可以与基础 Java 攻防同批落地。它们必须参与实际攻击/防御，不只出一张能力表。现有 TxF 文件事务后端继续复用，但它本身不提供实体防护。

玩家入口保持“发行 JAR 放进 mods，正常启动 Forge”。首选实际可用的 Forge/ModLauncher 早期入口自动准备自有桥和基础 hook；不让玩家填 JVM 参数。缺少某项必要能力时只明确报告受影响范围，已有准确动作继续；不能显示完整可用。Secret 的静态构造前加载可参考，但不等于自动取得 premain 的全部早期覆盖。

完整 Host 阶段继续做实际权限、驱动、模块、进程/线程与文件控制。重点是实际能够拒绝的访问、创建或 I/O 入口；系统授权和签名条件照实处理。当前 JVM 的一份 DLL 不等于管理员/内核权限。A 依赖的准确底层动作提前，其他 Host 生命周期仍归 C，不先空建平台工程。

## 5. 按整批推进

| 批次 | 一次写齐的范围 | 本批要看到的结果 |
| --- | --- | --- |
| A 返修 | 直接清体、真实写入防护、准确源剪断/回填阻断、任务最短控制链、实际分派、基础客户端和必要 Native/免参引导 | 能直接清、能在实际位置防；已确认恢复路径失效；合法对象与玩家交互继续 |
| B 收口 | 所有声明来源、后继、等待者和资源；保存流/句柄、Native 提交及原意图重启 | 临时压制解除后旧源不回来，任务/资源真正结清，保存后重启仍成立 |
| C 扩展 | 完整世界/字段、动态代码、Native/Host、通信与呈现资源图、视觉 | 兑现各实际后端的完整控制范围 |
| D 交付 | 整合迁移、长期运行、性能/体积与发行 | 同一候选的必要范围通过，交付 JAR、哈希和失败修复说明 |

实现优先修改现有 `ProRuntime / ProtectionHooks / EntityRecords / Access / RecoverySources / TaskBridge / RecoveryTasks / ProNetwork / ClientPresence / RecoveryAgent` 与已有 Native 桥。新增小组件必须对应确实缺失的生产入口；不按每个字段、权限、场景编号复制类。

## 6. 验证放在整批之后

编码中只做必要编译排错，整批写完后集中检查六组：

1. 真实字段、所有适用索引与呈现登记确实清掉；目标空方法和回调异常不能封死独立步骤。
2. 停后置修复仍防住；主线程/worker、直接字段/集合操作都产生真实攻击尝试。
3. 已确认包装源、无 NBT、新 UUID、0ms 与迟到任务确实被处置。
4. 同类邻居、共享池、合法换身/传送、撤销、输入和无关绘制正常。
5. 本批涉及的释放、保存/ACK 故障、提交和重启结果真实；未知操作不重复执行。
6. 必要启动/Native 路径来自正常玩家入口；负载下能继续运行，旧失败有对应回归。

复用现有场景和工具，不增加 runner。未改动且没有新问题的检查不反复重跑；未执行的检查保留 NOT_RUN。完整矩阵是阶段交付时的查漏表，**不是普通攻击调用前的门槛**。
