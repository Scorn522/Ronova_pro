# V1.4 实施接续与版本差异

修订：R3 · 实际执行权与直接实施。本次仅改设计与清单，输入源码包和历史证据未修改；以下历史代码状态仍属于同一 WIP。

## 1. 本版与 V1.3 的关系

保留 16 组 Primitive、10 项 Executor 职责、O01–O05、C01–C39、20 tick 稳定窗口和不超过 10 tick 的采样间隔。保留 Execution-first / Primitive-first、旧语义追踪附录、已有 Native/任务/重启实现及完整后续能力目标。

本次改变的是基础的具体内容和验收标准，不新增一套流程框架：

| 条目 | 变化 |
| --- | --- |
| 基础攻击 | 先封已确认源与回填/首次发布，再直接处置原身体/记录；目标的空方法/免疫返回不否决准确原语；源未知不冻结全部已知动作 |
| 基础防御 | 前置主防线必须独立成立；修复只计事故兜底。即时激活、主线程/worker 共用准确短门、真实写入/发布前拒绝，玩家同样支持 |
| SOFT | 增补当前会话临时 guard 的明确边界；不创建持久资格，不等待该次日志；不可逆步骤仍走 HARD |
| 载体替换 | 非法替换优先发布前拒绝；合法替换有策略原子交接，工作线程与旧读者无空窗；重定位仅处理确实已发生的事故 |
| 来源 | 首次写盘前发现，准确 source 消费/producer/工厂输出在首次副作用前或最早可归属发布前受控；包装与无 load 都是必需路径 |
| 完成 | 空工作表不证明没有来源；延迟重建必须进反例；正确报未决不能代替正例成功 |
| 实施顺序 | A 同批完成实际代码/分派、准确源控制与基础 UI 的通用攻防 → B 补齐来源广度/恢复链 → C 完整控制面 → D 统一交付 |
| 编写节奏 | 一次完成生产整批后集中验证；不按按钮、字段、子用例复制框架 |
| 玩家启动 | 放入发行 JAR 后正常启动 Forge，免手填 Ronova 专用 JVM 参数；自动加载不降低功能合同 |

## 4. 审阅后的成批实施

**R3 的最新写法优先于下方历史演进措辞：** 先照 [直接实施方案](直接实施方案-V1.4-R3.md) 写真实入口和动作。准确内存清体/索引/已确认内存源直接处理，不统一等完整来源、持久 ACK 或专用许可；写盘、Host、持久权威和未知不可安全重复操作单独接续。已有资源和任务结算复用，不新建一层框架。

A 同批加入实际 backing/旧别名/批量操作、必要 native 绑定、准确派生和本方关键资源防拆；B 补全部来源和文件真实句柄路径。编号与角色不变，验收放在整批写完后集中做。当前只交方案，生产源码继续暂停。

不是每个 Sxx 发一个版本，也不是先写完整证书框架。已有 Subject/Binding/CommitGate、准确 EntityRecords、TaskBridge 和 Native beginCommitFor 优先复用；每批必须把真实入口、执行及必要检查一起写齐，再集中运行关键组合。

### 批次一（Stage A 返修）：先交付能实际攻防的完整基础链

**启动依赖与最短纵向切片一起做。** 先明确玩家无手填参数的实际早期引导；当前 premain 依赖与拒绝 agentmain 事实不能靠文案解决。内部受控启动参数允许自动维护，但完整链可核查，不能要玩家手动改 JSON/填 Agent；只在支持组合上声明。A 实际需要的 Native 执行桥同批写，未采用的 Host/驱动不空建安装工程。

**同批生产动作：**

- 先在基础实际代码/载体/handler 投入使用前准备共用门，非目标正常放行；请求时只发布当前保护/封锁快照。SESSION_GUARD_ACTIVE 不等 durable ACK；跨线程准确对象索引不依赖被篡改的 raw level 反查 runtime，不跨线程直接改可变世界图。
- 对真实生命/最大生命/状态 writer、登记、容器和 carrier 发布点实施双向写入控制；基类 HEAD 保留但不能代替覆盖方法/DataItem/集合视图。PR12/13/15 同批完成准确方法/分派/返回控制、目标相关防御实现条件性失能和本方反全返回；不只取得字节指纹。
- 保护不等完整攻击者来源图。攻击不等 executed CLEAR 才封回插；已确认包装记录份额、真实工厂输入/输出及当前任务/回调写回同批前移，既封发布也直接剪准确可幂等内存源，持久和未知副作用单独接续。源码落点复用 RecoverySources/Records/References、TaskBridge/RecoveryTasks，不增加独立源框架。
- 身体/索引清理不被对方 callback 失败或无关容器缺口整体挟持；已确认独立幂等动作继续，未知副作用不盲重放。维护不因一张表故障停止全部可执行保护。载体重绑定的旧工作与 capturedCallback 引用做真实交接释放。
- 复用操作级定序处理合法撤销/跨维度/重生/载体替换；精确限定重入例外。必要门的实际版本连续性在本批完成，不能留到 C 才发现基础根本没拦截。
- BlockEntity 与真实客户端分别落地；准确玩家非法位移/合法换身、镜像/Tracking、HUD/BossBar、已绑定 draw 份额及 UI/输入前置控制在本批完成。不可拿 absent 探针代替，合法 ESC/背包/菜单/断连保持正常。原维护修复是独立事故结果。

**集中验证：** 复用既有基础攻防/恢复源组合，增加的是前移生产路径而非用例 ID/runner。覆盖矩阵 §2.1 中 C04–C09/C25 的 A 范围，以及原 A 基础组合；慢 ACK、worker、停修复、实际 writer、合法邻居与解除保护都保持真实效果断言。已有历史失败不自动关掉。

### 批次二（Stage B 返修）：补齐源/任务广度与实际整链终结

**同批生产动作（A 已落地的直接能力复用，不重写）：**

- 补齐全部声明的未保存/静态/包装来源与共享边；HashMap 的实际并发协议明确，不能把只读发现变成整体删除授权。
- producer 输入/源读取/工厂副作用之前能够精确归属就先拦；只能输出确认时在第一次危险发布前拦。覆盖普通构造/部分赋值/无 load，而不只 clone/NBT。
- TaskBridge 同步判本次 invocation；0ms 不能靠延迟化让测试绿。观察排队/合并用于后续结算，不决定已知拒绝何时生效。在途 frame 的非法提交与迟到后继受控，真实 EXIT/等待者/引用/资源仍独立结清。
- 第三方非法保存在真实 open/truncate 前拒绝，自有 Native beginCommitFor 保持提交前复核；不损坏原基线/邻居，原 Intent 未知结果查询与重启不改。
- 源准确处置后做临时压制释放试验，区分 SUPPRESSED 与旧源已终结；独立蛋生成的新目标允许正常存在。

**集中验证：** C04/C05/C06–C19 与相关前置变体，包含完整 holder、无 NBT、新 UUID、旧保存、晚到/重排/在途任务、并发 commit/revoke、Native 故障/重启。再回归受影响 A 项，不重复无变更的所有无关测试。

### 后续批次（C / D）：完整控制面与统一交付

沿主设计扩展世界/全字段与种子重生成、完整动态代码/调用/定义、全域 Network/Input、纯渲染/Presence 资源图、授权 Host 后端及视觉。A 的必要代码控制、基础 UI/输入/准确呈现不在此时才第一次开写。全部以源/入口/写入/发布前效果为主，通知和事故恢复另算。动态类和已运行活栈分开；Native/Host 必须有实际可否决点才计拦截。

D 做迁移、长期压力、队列/资源/预算下零穿透与正常业务进展、真实发行和重启。保留 39 父场景；新增机制子用例不是 39+N 套服务。

### 本批明确不做

不删除实际清体、身份/lineage、HARD 授权、资源释放和真实退出/持久查证；不凭 `terminal=true` 声称 MC/JVM 会自动执行策略；不把系统通知当万能阻断；不靠全类型黑名单、关共享线程池或停整个世界制造“打不到”。

本次只更新 MD，以上都是接下来的实施要求。没有改变现有 WIP 的 compile/runtime 状态，也没有生成新游戏 JAR。
